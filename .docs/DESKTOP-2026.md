# Мультиплатформенное десктопное приложение: практики на август 2026

Что считается нормой для настольной программы под Windows и Linux **сегодня**,
и как это ложится на «Терминал». Проверено по состоянию на 30.08.2026.

Стек зафиксирован ТЗ ([`SPEC.md`](SPEC.md) §6): Python + PySide6. Средство сборки
пересмотрено решениями [0001](decisions/0001-packaging-nuitka-portable.md)
и [0002](decisions/0002-no-code-signing.md) — Nuitka вместо PyInstaller, портативная
поставка без установщика, подписи кода не будет.

Этот документ описывает, **как** делать правильно внутри принятых решений,
и почему каждое отклонение от буквы ТЗ осознанное, а не случайное.

---

## 1. Сборка: Nuitka, а не PyInstaller

Решение принято ([0001](decisions/0001-packaging-nuitka-portable.md)) и следует
из другого решения: [подписи кода не будет](decisions/0002-no-code-signing.md).

### Почему антивирусы — это про PyInstaller, а не про Python

Ложные срабатывания на «упакованном Python» — расхожая формулировка, и она неточна.
Проблема конкретно у PyInstaller, по двум причинам:

1. **Загрузчик (bootloader).** Один и тот же бинарный стаб во всех сборках мира.
   Он попал в списки угроз ряда антивирусов сам по себе — независимо от того,
   что за программа внутри.
2. **UPX-сжатие по умолчанию.** Упаковщики используются малварью для ухода
   от детекта, поэтому сжатый файл — отдельный признак для эвристик.

Режим `--onedir` убирает третью причину — самораспаковку во временную папку
при каждом запуске. Загрузчик и UPX остаются. То есть `--onedir` лечит симптом.

**Nuitka устроена иначе:** компилирует Python в C и линкует нативный бинарь.
Загрузчика нет, архива с байткодом нет — для эвристик это обычная программа.
Замеренный в открытых источниках эффект перехода: **с 11 срабатываний из 60 до 1 из 60**.

Qt официально рекомендует именно этот путь для PySide6: `pyside6-deploy` —
обёртка над Nuitka. Лицензия Nuitka — Apache 2.0, коммерческое использование бесплатно;
Nuitka Commercial существует, но это опциональная подписка для защиты кода, нам не нужна.

### Цена и чем она закрывается

| Цена | Чем закрывается |
|---|---|
| Сборка десятки минут на Qt-проекте | Платится в CI раз на релиз; разработчик запускает из исходников |
| Регрессии между версиями Nuitka (собиралось на 1.86, ломалось на 1.9–2.01) | Версия жёстко зафиксирована; обновление — отдельная задача с прогоном |
| Поломки Qt-плагинов разбираются тяжелее: пустое окно, падение на старте | Обязательный прогон на чистой машине под обе ОС |
| PyInstaller мог бы понадобиться | `.spec` поддерживается и собирается в CI как запасной путь |

### `--onefile` не используется нигде

Ни у Nuitka, ни у PyInstaller. У обоих он самораспаковывается во временную папку
и возвращает часть проблемы с эвристиками. Только `--standalone`.

## 2. Поставка: портатив, установщика нет

| Платформа | Что получает пользователь |
|---|---|
| **Windows** | Папка с `Терминал.exe` и всем нужным. Копируется куда угодно, работает с флешки |
| **Linux** | **Один исполняемый файл** `Терминал.AppImage`: `chmod +x`, запуск. Ни root, ни демона, ни магазина |

**Доустанавливать нечего.** Python, Qt, pandas, httpx — внутри бинаря. Требование ТЗ
«пользователь не устанавливает Python и ничего не настраивает вручную» выполняется
в более сильной форме, чем через установщик: не устанавливается вообще ничего.
Удаление = удалить папку или файл.

### Первый запуск

Базу и папку данных создаёт **сама программа**, а не внешний скрипт: скрипт,
который можно забыть запустить, — лишняя точка отказа. При старте программа
создаёт папку данных рядом с собой, схему SQLite, файл настроек с умолчаниями
и правами только владельцу, и пишет в журнал, что было создано.

### Грабли, которые ловятся только прогоном на чужой машине

| Платформа | Грабли |
|---|---|
| Windows | Сборка через MSVC тянет VC++ Redistributable. Собирать `--mingw64` — бинарь самодостаточен |
| Linux | Сборка на свежей базе требует свежий glibc. Собирать **на старой LTS в контейнере** |
| Linux | **FUSE.** AppImage монтирует себя через FUSE, и на части свежих дистрибутивов нет `libfuse2` — файл просто не запускается. Решение: новый формат AppImage (fuse3) или `--appimage-extract-and-run` |
| Linux | **Wayland.** Без `libqwayland*` в сборке падает только на Wayland-сессии, на X11 всё в порядке |

### Почему не Flatpak и не `.deb`

Flatpak на 2026 год — стандарт раздачи десктопного Linux, но он про публичную раздачу
через Flathub: песочница, ревью, магазин. Нам это мешает — программе нужен доступ
к файлу с токеном и к папке рядом с собой, а раздачи нет вовсе.

`.deb` + `systemd` добавляется, только если Linux окажется постоянно работающей машиной
(открытый вопрос №12). До ответа — AppImage.

## 2-Б. Подписи кода не будет — что из этого следует

Решение [0002](decisions/0002-no-code-signing.md). Вариант существовал: Azure Trusted
Signing (в 2026 переименована в Azure Artifact Signing), от ~$10/мес, без HSM-токена,
сертификаты живут 24 часа. Ограничение: только проверенные организации и самозанятые
из США, Канады, ЕС и Великобритании. Юрлицо под это не заводится — вопрос закрыт.

Справочно, чтобы к вопросу не возвращались: `Microsoft Windows Production PCA 2011`
истекает 19 октября 2026, к концу года Windows переходит на RSA-3072 и SHA-384.
Нас это не касается, поскольку не подписываем.

**Обязательные меры при отсутствии подписи:**

⬜ UPX не используется нигде и никогда
⬜ Имя и структура сборки стабильны от релиза к релизу — меняющееся имя выглядит
   для репутационных механизмов как новая неизвестная программа каждый раз
⬜ Ложные срабатывания отправляются вендорам антивирусов: у всех крупных есть форма,
   разбор занимает дни. Это штатная процедура релиза, а не аварийная
⬜ В инструкции пользователя — отдельный раздел со скриншотами: что показывает Windows
   при первом запуске, почему, и как пройти («Подробнее» → «Выполнить в любом случае»).
   Прямым текстом, без попытки замять

## 3. Автообновление

Программа торгует деньгами. Молчаливое автообновление, которое подменит торговую
логику посреди сессии, — недопустимо.

**Практика для этого класса программ:**

- проверка новой версии при старте, **никогда** во время открытой позиции;
- обновление только по явному согласию пользователя;
- показ, что именно изменилось, до установки;
- откат на предыдущую версию как штатная возможность (папка предыдущей сборки сохраняется);
- **версия программы пишется в журнал решений** при каждом старте — иначе разбор
  «почему в тот день робот повёл себя иначе» невозможен.

Подписанные обновления обязательны, если подпись вообще есть: обновление — это канал
доставки кода на машину с доступом к брокерскому счёту.

## 4. Секреты

ТЗ §4.1 требует хранить токен **в файле рядом с программой** — это осознанное решение
заказчика, и оно не оспаривается. Но отраслевая практика 2026 года — системное хранилище:

| Платформа | Штатное хранилище |
|---|---|
| Windows | Credential Manager / DPAPI (шифрование привязано к учётной записи) |
| Linux | Secret Service (GNOME Keyring, KWallet) |

Разница существенная: файл рядом с программой читается любым процессом от имени
пользователя и уезжает в резервную копию папки вместе со всем остальным.

**Что делаем:** файл — как требует ТЗ, **плюс** обязательный минимум:

- отдельный файл, права `0600` (Linux) / ACL только владельцу (Windows);
- токен не попадает в технический лог, журналы, отчёты и экспорт — ни целиком, ни частично;
- в интерфейсе показывается маска, а не значение;
- системное хранилище — как **опция** в настройках, если заказчик согласится.

Это записано отдельным решением в [`decisions/`](decisions/) и проговорено с заказчиком,
а не решено молча.

## 5. Программа должна дожить до конца торгового дня

ТЗ §7 называет «компьютер выключен или уснул» риском высокой серьёзности. Это решается кодом:

| Задача | Windows | Linux |
|---|---|---|
| Не дать машине уснуть, пока робот в работе | `SetThreadExecutionState(ES_CONTINUOUS \| ES_SYSTEM_REQUIRED)` | `systemd-inhibit` / D-Bus `org.freedesktop.login1` |
| Один экземпляр программы | ~~именованный мьютекс~~ → `msvcrt.locking` | lock-файл с `flock` |

⚠️ **Строка про именованный мьютекс отменена 05.09.2026**, см. решение
[`0039`](decisions/0039-one-copy-per-data-folder.md). Мьютекс ключуется **именем**,
а замок нужен **на папку данных**: две копии программы с разными папками мешать
друг другу не должны, а две копии с одной — обязаны. На Windows взят приём SQLite:
`msvcrt.locking` по смещению за пределами содержимого файла. Замок живёт в ядре,
поэтому после аварийного завершения не остаётся вовсе — чистить нечего.
⚠️ Ветка Windows не исполнялась ни разу, это условие приёмки и оно не выполнено.
| Не потерять состояние при закрытии окна | перехват закрытия: если есть открытая позиция — предупреждение, а не тихий выход |

**Один экземпляр — не удобство, а защита денег.** Две копии программы на одном счёте
подадут две заявки на один сигнал.

## 6. Интерфейс

| Практика 2026 | Что значит для нас |
|---|---|
| **HiDPI** | Qt 6 масштабирует сам, но иконки нужны векторные (SVG) или в нескольких размерах. Проверка на 100%, 125%, 150%, 200% |
| **Тёмная тема** | Qt 6.5+ подхватывает системную. Цвета свечей, меток сделок и линий уровней обязаны читаться в обеих темах — на графике это не косметика, а различимость лонга и шорта |
| **Клавиатура** | Порядок обхода Tab, видимый фокус, Enter/Esc в диалогах. Владелец счёта работает быстро и мышью не всегда |
| **Ничего не блокирует окно** | Любая операция дольше ~100 мс — асинхронно или в поток, с индикатором. Замерший интерфейс во время обрыва связи выглядит как зависшая программа |
| **Часовые пояса** | Всё торговое время — **МСК**. Машина заказчика может стоять в другом поясе. Время в UI и в журналах помечено поясом явно; внутри — осознанный единый выбор (UTC или МСК), зафиксированный решением |
| **Русский язык** | Интерфейс, журнал решений и сообщения об ошибках — по-русски, человеческим языком. Код ошибки брокера — это не сообщение пользователю |

## 7. Асинхронность

Qt и `asyncio` сводятся в один цикл событий одним из двух способов:

- **QtAsyncio** (`PySide6.QtAsyncio`) — официальная реализация от Qt;
- **qasync** — зрелая сторонняя библиотека, декоратор `@asyncSlot`, `run_in_executor`
  с `QThreadExecutor` для тяжёлых вычислений.

Выбор фиксируется решением с обоснованием. Смешивать оба в одной программе нельзя.

**Тяжёлые вычисления — не в цикле событий.** Оптимизатор перебирает сотни комбинаций
параметров; в цикле событий это замораживает окно целиком. Перебор идёт в отдельных
процессах, прогресс отдаётся сигналами.

## 8. Сборка и выпуск

| Практика | Зачем именно здесь |
|---|---|
| **Матрица CI: Windows + Linux** | Пункт приёмки §9 — «одна и та же программа поставлена и отработала на Windows и на Linux». Проверяется машиной, а не обещанием |
| **Закреплённые версии зависимостей** (lock-файл) | Сборка, воспроизводимая через полгода. Молчаливое обновление `pandas` меняет числа в отчёте |
| **SBOM** (состав сборки) | Что именно попало в поставку. Для программы с доступом к счёту — обязательная гигиена |
| **Прогон сборки на чистой машине** | Единственный способ поймать «а у меня Python не установлен», отсутствующие системные библиотеки, VC++ Redistributable, glibc, FUSE и Qt-плагины |
| **Версия Nuitka зафиксирована** | Регрессии между версиями были: собиралось на 1.86, ломалось на 1.9–2.01 |
| **`.spec` PyInstaller собирается тем же прогоном** | Запасной путь обязан оставаться рабочим, а не протухнуть |
| **Версия в интерфейсе и в журнале** | См. §3 |

## 9. Сводка отклонений от ТЗ

| Тема | ТЗ | Что делаем | Решение |
|---|---|---|---|
| Сборка | PyInstaller | **Nuitka standalone**; PyInstaller — рабочий запасной путь | [0001](decisions/0001-packaging-nuitka-portable.md) |
| Поставка | «один исполняемый файл», установка не требуется | **Портатив без установщика**: Windows — папка, Linux — один файл AppImage. Не устанавливается вообще ничего | [0001](decisions/0001-packaging-nuitka-portable.md) |
| Подпись кода | не упомянута | **Не подписываем.** Меры по антивирусам вместо неё | [0002](decisions/0002-no-code-signing.md) |
| Хранение токена | файл рядом с программой | Файл по ТЗ + строгие права и исключение из логов; системное хранилище как опция | открытый вопрос |
| Формат под Linux | не указан | AppImage; `.deb` — если Linux окажется постоянно работающей машиной | открытый вопрос №12 |

Требование ТЗ §6 «пользователь не устанавливает Python и ничего не настраивает
вручную» выполняется полностью и в более сильной форме, чем предполагалось:
установки нет как этапа.

Каждое отклонение оформлено файлом в [`decisions/`](decisions/) и проговаривается
заказчику. Молча отступать от согласованного ТЗ нельзя — даже когда отступление
технически правильное.
