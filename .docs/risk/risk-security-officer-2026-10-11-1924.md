### 1. 🟡 Плашка «Данных нет» велит скопировать `userdata` с ключом. После этого две папки программы с одним ключом запускаются одновременно

**Что делает.** `app/userdata_notice.py:55-58`: если новая версия распакована не туда, плашка
говорит «закройте обе копии… **скопируйте** папку userdata из прежней папки программы сюда».
**Для кого.** Для владельца счёта, который обновился «не в ту папку» (`Terminal\Terminal\`).
**Что сломается.** После копирования есть две папки, в каждой своя программа и один и тот же
`broker-token.json`. Замок «одна копия» стоит **на папку данных**, а не на счёт
(`app/single_instance.py:51-55`, решение 0039, долг Э1-9). Поэтому старый ярлык на рабочем
столе и новый `Запустить.bat` запускаются оба. В бою это два робота на одном счёте: две заявки
на каждый сигнал, позиция двойного объёма. Потолка объёма на этапе нет (D-113), удвоение
ничем не ограничено.

* Сценарий: обновление в `Terminal\Terminal\` → плашка → копирование `userdata` → запуск
  нового. Позже старый ярлык запущен «по привычке». Замок старой папки свободен, второй
  экземпляр стартует.
* Достижимость: 🟡 **на этапе боевого исполнителя (Э1-9)**. Сегодня заявок к брокеру нет,

* Требование (на выбор владельца счёта, к Э1-9): либо слово «**перенесите**» вместо
  «скопируйте» в плашке, с отдельной резервной копией по README, либо замок по счёту
  до первого боевого запуска. Сегодня в работу не идёт.

### 2. Замечание о прежнем тексте README: в копии «про запас» лежит ключ к счёту, а текст об этом молчит

**Что делает.** README обеих поставок, раздел «Как обновить» (`tools/windows_package.py:135`,
`tools/linux_package.py:101`), велит скопировать папку `userdata` «куда-нибудь про запас».
**Для кого.** Для владельца счёта.
**Что сломается.** В этой папке лежит `broker-token.json`. На Windows «куда-нибудь» — это
обычно рабочий стол или «Документы», а у многих они синхронизируются с облаком. Ещё бывает
флешка без ACL. Файл ключа уезжает туда с правами места назначения. Кто получил копию,
получил доступ к счёту в пределах прав ключа, и для этого наш боевой исполнитель не нужен.
На Linux `cp -r` сохраняет 0600 при обычном umask, там риск ниже.

* Ухудшения нет. Строка про копию стояла в README Windows и раньше («2. Скопируйте папку
  „userdata“ куда-нибудь про запас»). В README Linux раздел новый, но права там сохраняются.
* Достижимость: 🔴 по тексту инструкции, проверяется чтением README. Утечка случается
  только при действии человека.
* Требование: одна фраза в обоих README. Например: «В копии лежит ключ доступа к счёту.
  Храните её там, куда нет доступа у других и что не синхронизируется с облаком, или уберите
  из копии `broker-token.json`: ключ можно получить у брокера заново». Решает владелец счёта,
  коммит этим не блокируется.

### 3. ⚪ Запись строк симуляции стоит в проходе перед `_remember_halt`

`LiveObserver.feed` теперь ждёт `PaperLog.flush` (`app/observe.py`, конец `feed`), и только
потом порт запоминает остановку движка (`app/port.py:3682-3686`). Сама остановка в движке

не стоит. Если боевой исполнитель пойдёт тем же путём, свидетельство не должно стоять между
