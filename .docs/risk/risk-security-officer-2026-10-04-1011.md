### Замечания

1. 🟡 Э4 — **Срок жизни заявки «до конца дня» против счёта ожидания в свечах.**
   Что делает: `_closing_wait` считает свечи ожидания лимитного выхода и на
   `time_exit_wait_bars` останавливает робота словами «заявка осталась у брокера».
   Для кого: владелец счёта при окне, кончающемся за ≤ N свечей до конца сессии
   (окно настраивается; на умолчании 09:30–11:30 недостижимо).
   Что сломается: последняя свеча дня — выход не исполнился — свечей до вечера нет;
   по контракту порта (`timeInForce "1"`) заявка снимается биржей вечером, а
   остановка и строка ERROR придут только на первой свече следующего торгового дня
   (после выходного, если это прощальный выход по решению 0038). Позиция
   перенесена через нерабочий день без тейка, человек узнаёт утром, и текст
   «заявка осталась у брокера» к тому моменту неправда.
   Тестер (`backtest/execution.py`, правило 5 шапки) в том же случае держит заявку
   через ночь и исполняет её по `open` следующего дня (`at_later_open`) — то есть
   моделирует бессрочную заявку при дневной в контракте порта. Счётчик отдельный,
   но сделка в отчёте есть, а в бою её бы не было.
   Требование к Э4: либо остановка на последней свече сессии при висящем пределе,
   либо срок жизни заявки, согласованный с тестером; текст «осталась у брокера»
   — только если это так. Воспроизведение: прогон тестера с окном, кончающимся
   на последней свече сессии, `LIMIT`, большой отступ отрицательного направления
   не нужен — достаточно разрыва через предел; не прогонялось.

2. 🟡 Э4 — **Шаг цены из окна не сверяется с инструментом.** Шаг вписывается
   руками (решение владельца: из карточки не подставлять). Шаг не кратный
   настоящему → предел не на сетке биржи → отказ брокера → путь
   `exit_blocked_bars`: заявка переподаётся каждую свечу, затем остановка.
   Денег не теряет (отказанная заявка в стакан не встаёт), но выход по концу
   окна не происходит. Предложение к Э4: сверка вписанного шага с карточкой
   инструмента строкой журнала, без подстановки.

3. 🟡 Э4 — **Подмена LIMIT→MARKET при запуске для алгоритма №2.** При шаге 0
   программа стартует с выходом «по рынку» при выбранном алгоритме №2, который
   требует предела; сказано строкой ERROR «Настройки не приняты» с прямым
   указанием, что требование алгоритма не выполнено (`_stepless_note`). Сегодня
   это прогон на экране — допустимо и видно. Для боевого режима подмена способа
   выхода при запуске недопустима: `/go-live` должен требовать отказ запуска,
   а не подмену.

4. ⚪ Частичное исполнение лимитного выхода не обрабатывается — названо
