## Ответы на шесть вопросов координатора

### 1. Достаточно ли заморозки `guard_note`

**Нет — на одной оси.** 24 клетки × точный текст закрывают все склейки по четырём осям
(G1–G5, G8, G11, G12 упадут — это верно). Но внутри восьми клеток `ARMED` ещё две оси
подстановки, и план фиксирует их **на одной клетке** (§3(а): «плюс шесть подстановок
на одной клетке»). Итого заморожено 13 из 48 строк `ARMED`, **35 строк не заморожено**.
Подробно — находка R1.

Остальное заморозка покрывает: умолчание `Context()` громкое
(`test_a_forgotten_context_is_the_loud_one`); `unmanaged_note` принудительно снимает
`managed` — не трогается; панель зовёт `Context.of(state)` — мутация GX4 (подмена
на `Context()`) роняет 3 теста сегодня; неизвестное значение `take_trailing` —
`test_an_unexpected_trailing_flag_does_not_break_the_panel`.

### 2. Клетка `ARMED × closing`

**План прав: из движка это состояние не приходит.** Проверено чтением и прогоном.

Чтением: `_exit` (`engine/pipeline.py:1281-1313`) при `armed_before` подаёт снятие
**до** закрытия; `after_submit` на принятом снятии гасит уровень (`_after_cancel`, `:451`);
`_submit_all` (`engine/runner.py:539-580`) останавливает подачу на **первом** отказе —
закрытие после отвергнутого снятия не подаётся, позиция остаётся `OPEN`; `_settle`
(`:1536`) выбрасывает вооружение на свече выхода; шаг 5 закрывающуюся позицию
не вооружает (`:1114-1123`). Раннер собирает состояние только по принятым заявкам
(`runner.py:520-521`).

Прогоном (скрипт — приложение А), инвариант «`CLOSING` ⇒ `take.level is None`»
после **каждой** свечи:

| конфигурация | свечей в `CLOSING` | нарушений |
|---|---:|---:|
| 10:05–11:00 + выходные, тейк 0,5 % | 75 | 0 |
| 10:05–11:00 будни, тейк 0,5 % | 53 | 0 |
| 09:30–11:30 + выходные, тейк 0,5 % | 106 | 0 |
| 09:30–11:30 будни, тейк 0 | 166 | 0 |
| 10:05–11:00 + выходные, 0,5 % + скользящий | 87 | 0 |
| отказ в снятии `ALREADY_TRIGGERED`, каждое 3-е | 67 | 0 |
| отказ в снятии `UNKNOWN`, каждое 5-е | 71 | 0 |
| отказ в закрытии, каждое 3-е (и с трейлингом) | 67 / 82 | 0 / 0 |

Решение оставить клетку как есть — верное, и текст в ней **верен для единственного
пути, которым она может прийти**: сверка позиции с брокером после обрыва (DOMAIN.md §7),
когда `app/` соберёт `Position` из настоящего списка заявок и увидит и стоп, и висящий
рыночный выход. Две заявки — ровно то, что владелец счёта обязан услышать. Разбирать
клетку сейчас не надо. Два замечания — R3 и R4.

### 5. Знак шага подтяжки

**Цена в рублях сегодня — ноль, и пометка 🟡 верна.** Разбор: отрицательный шаг
в поле не вводится; пришедший из кода `Settings(trailing_step_pct=-0.1)` до движка
не дойдёт мимо диалога (`convert.engine_settings` → `EngineSettings` отказывает,
порт пишет «Значение не годится»); диалог покажет «0,00 % — без ограничения», по «ОК»
уйдёт 0, движок 0 **принимает**, а в журнале появится строка «шаг подтяжки: 0,05 → 0»
относительно последнего принятого значения — подмена тихая **в окне**, но не в журнале.
Что означает 0 для денег: уровень переставляется на каждой новой лучшей цене —
«до двенадцати обращений к брокеру за час позиции» (подсказка поля), в лимит 10 rps
укладывается. Прямого убытка нет.

⚠️ Тот же класс с настоящей ценой — `volume=0 → 1` и `volume=-3 → 1`: движок ноль
**отвергает**, окно превращает его в заявку на один контракт MXU6 (номинал порядка
284 000 ₽, ГО — десятки тысяч). И `daily_loss_limit_pct=-5 → 0 = «лимита нет»`:
негодное значение предохранителя становится «предохранителя нет». Запись долга
обязана ранжировать по этому, а не по шагу подтяжки.

## Находки

### R1 🔴 Заморозка `guard_note` оставляет 35 из 64 строк без сторожа — блокирует план (правится текст плана, не код)

**Что делает / для кого / что сломается.** `guard_note` собирает предложение про
уровень выхода из трёх слов (`скользящий тейк` / `тейк` / `уровень выхода`) и числа
уровня; читает его владелец счёта, решая, ставить ли свой стоп и ждать ли, что уровень
сдвинется. Сломается слово: скользящий уровень назван неподвижным «тейком» — комментарий
`ui/notices.py:170-172` сам называет это неправдой («он мог уехать далеко от цены входа»).
Число при этом остаётся верным (`take_level` — текущий уровень), поэтому цена
в рублях — не позиция, а ложное ожидание, что уровень стоит на месте.

**Механизм.** План замораживает 24 клетки одной подстановкой (фикстура) и шесть подстановок
на одной клетке — по действующим тестам это клетка «бой × без робота × открыта»
(`test_trailing_level_is_called_by_its_name` и соседи зовут `guard_note(...)` с умолчанием
`Context()`). После разреза `what`/`level` перестают считаться один раз перед ветвлением
и попадают внутрь `_take_sentence`; помощник, подставивший слово в одну ветку и
захардкодивший в другую, проходит и 24 клетки, и 6 подстановок.

**Воспроизведение сегодня (GX1):** в копии `ui/notices.py` заменить
`f"Выставленный {what}{level} существует только внутри программы"` на
`f"Выставленный уровень выхода{level} существует только внутри программы"`, прогнать
три файла окна — **367 passed**. Под запланированной заморозкой останется зелёной:
фикстура тестов (`take_trailing=None` → «уровень выхода») совпадает с захардкоженным
словом во всех восьми клетках `ARMED`, а клетка подстановок — не симуляционная.
Для сравнения GX3 (число уровня выброшено в боевой ветке) падает на 12 тестах —
число сторожится, слово нет.

**Требование.** §3(а) и §5 шаг 1: заморозить **все 64 строки** — 8 клеток `ARMED` ×
3 значения `take_trailing` × 2 значения `take_level`, плюс 16 остальных;
параметризация, цена — ноль. Мутацию GX1 добавить в список «обязана упасть» §7.

### R2 🟡 Запись долга по подрезке неполна — в `ROADMAP.md` §9.10, тем же изменением, что заморозка

**Что делает / для кого / что сломается.** Границы полей диалога молча подменяют
число, пришедшее в `set_values` снаружи; страдает владелец счёта, когда появится
первый путь снаружи (файл настроек, восстановление после перезапуска, числовые ключи
командной строки) — параметр по деньгам уйдёт по «ОК» не тем, что записан, и в журнале
подмена будет видна только относительно последнего принятого движком значения.

**Достижимость:** 🟡 — сегодня путей снаружи нет (проверено, §4б). Становится 🔴
в момент появления любого из трёх путей выше — **и это должно быть названо в записи
как триггер**, иначе долг никто не вспомнит. Для `daily_loss_limit` и `volume_cap`
второй триггер — появление самих предохранителей в движке (этап 2).

**Требование к записи (план говорит «три клетки подрезки с `# ДОЛГ`» и «семь из восьми»
— недостаточно):**
1. перечислить **все** поля с границей и наблюдаемой подстановкой — таблица из §4(а),
   15 строк, а не 8; ранжировать по цене: `volume 0/−3 → 1` (движок отвергает, окно
   выпускает заявку), `volume_cap 0 → 1`, `daily_loss_limit −5 → 0 «лимита нет»`,
   `take_profit −1 → 0 «тейка нет»`, затем верхние границы, затем округление;
2. назвать триггер достижимости (выше);
3. заморозка `test_ui_settings_freeze.py` фиксирует подрезку **всех четырёх полей денег**
   (`volume`, `volume_cap`, `daily_loss_limit`, `free_funds_reserve`) и шага подтяжки,
   каждая клетка с `# ДОЛГ` и ссылкой на запись §9.10 — не «три клетки»;
4. сторож `test_the_window_and_the_engine_agree_on_the_trailing_rule` слеп к оси шага
   структурно (перебирает только пары порог/отступ — проверено чтением
   `tests/test_ui_settings.py:713-758`); в записи сказать, что достроить его нельзя,
   не решив поведение окна на отрицательном шаге.

### R3 🟡 Инвариант «`CLOSING` ⇒ уровня нет» не утверждён ни одним тестом движка

**Достижимость:** 🟡 — сегодня инвариант держится (таблица §2). **Не в фазу 2**:

### R4 🟡 Клетка, где окно солжёт про деньги, — не `ARMED × closing`, а `NONE × closing × бой` при неподтверждённом снятии

**Что делает / для кого / что сломается.** Движок гасит уровень в момент, когда
исполнитель **принял** снятие (`_after_cancel`). Если боевой адаптер вернёт «принято»
раньше, чем брокер подтвердил снятие, а снятие не пройдёт (0008, открытый пункт
«снятие не подтвердилось до момента подачи закрытия»), движок покажет `CLOSING × NONE`,
и окно скажет «Выставленного уровня выхода у этой позиции нет» — при живом стопе
у брокера. Это ровно ложь из 0008: владелец счёта ставит свой стоп и получает два;
второй при следующем касании открывает позицию в обратную сторону на полный объём.

**Достижимость:** 🟡 — нужен боевой адаптер (Э1-9). Текст окна здесь не виноват и
не правится; требование — к приёмке адаптера: «принято» для `CANCEL_TAKE_PROFIT`
означает **подтверждение брокера**, а не отправку. Записать в §9.10 или в открытые
пункты 0008 ссылкой на эту находку.

## Приложение А. Скрипт инварианта (переносится в тесты движка фазой 5)

```python
# Инвариант: позиция в CLOSING никогда не несёт сторожимого уровня.
# Эталонные свечи → Engine + NextOpenExecutor, проверка после КАЖДОЙ свечи.
import asyncio, pathlib
from datetime import datetime, time
from engine import Engine, EngineSettings, Mode, TradingWindow, PositionState
from strategies import EmaReverse, EmaReverseSettings
from tests.engine_helpers import MSK, FakeCandle, FakeTimeframe, NextOpenExecutor

DATASET = pathlib.Path("reference/stand/install/data/Set_MoexFuturesMxu6/MXU6/Min5/MXU6.txt")
FROM, TO = datetime(2026, 6, 19, tzinfo=MSK), datetime(2026, 8, 26, 23, 59, tzinfo=MSK)
M5 = FakeTimeframe(5)
rows = []
for line in DATASET.read_text(encoding="utf-8").splitlines():
    p = line.strip().split(",")
    if len(p) < 6:
        continue
    m = datetime.strptime(p[0] + p[1], "%Y%m%d%H%M%S").replace(tzinfo=MSK)
    if FROM <= m <= TO:
        rows.append(FakeCandle(time=m, open=float(p[2]), high=float(p[3]), low=float(p[4]),
                               close=float(p[5]), volume=float(p[6]), timeframe=M5, filled_minutes=5))

def run(window, weekend, take, trailing=False):
    engine = Engine(EmaReverse(EmaReverseSettings(period=15)), EngineSettings(
        mode=Mode.REVERSE, window=window, close_on_time_end=True, trade_in_weekend=weekend,
        volume=1.0, stop_after_take_profit=True, take_profit=take > 0, take_profit_percent=take,
        trailing_take_profit=trailing, trailing_start_percent=0.5,
        trailing_offset_percent=0.2, trailing_step_percent=0.05))
    ex = NextOpenExecutor()
    violations = []
    async def go():
        for c in rows:
            await engine.on_market_candle(c, ex)
            pos = engine.state.position
            if pos is not None and pos.state is PositionState.CLOSING and pos.take.level is not None:
                violations.append((c.time, pos.take.level))
    asyncio.run(go())
    assert not engine.halted and not violations, violations

run(TradingWindow(time(10, 5), time(11, 0)), True, 0.5)
run(TradingWindow(time(10, 5), time(11, 0)), True, 0.5, trailing=True)
run(TradingWindow(time(9, 30), time(11, 30)), False, 0.0)
```

Вариант с отказами: подкласс `NextOpenExecutor`, чей `submit` на каждом N-м
`CANCEL_TAKE_PROFIT` / `CLOSE` бросает `ExecutionRefused("…", Refusal.ALREADY_TRIGGERED
| UNKNOWN | NO_SUCH_ORDER)`. Результаты 04.09.2026 — таблица §2 выше, нарушений 0.
⚠️ Для `NO_SUCH_ORDER` подделка обязана и **убить** сторож у себя, иначе она стреляет
сделкой по заявке, которой у движка уже нет, и робот честно останавливается —
это артефакт подделки, а не движка.
