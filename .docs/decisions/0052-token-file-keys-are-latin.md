# 0052. Имена полей в файле токена — латиницей, прежний формат читается всегда

**Дата:** 06.09.2026
**Статус:** принято
**Кто решил:** владелец счёта

## Вопрос

Файл `userdata/broker-token.json` держал имена полей по-русски: `версия`,
`токен`, `права`, `выпущен`, `счёт`. Это нарушение правила 6 `CLAUDE.md`
(«всё, что является именем, — латиницей»), но цена не в букве правила.

Цена была записана в самом коде, `broker/token_store.py`: образцы чистки логов
(`broker/redaction.py`) ищут **английские** имена полей — то есть единственное
место в программе, где токен лежит открытым текстом, было единственным, чьё имя
поля чистка не знала. Одна отладочная строка вида `log().debug("файл: %s", raw)`
вынесла бы файл с токеном в технический лог целиком.

Слова владельца счёта: «в файле тоже пусть всё на английском будет — называть
ключи кириллицей — то ещё дерьмо».

## Варианты

| Вариант | Последствие | Цена вопроса |
|---|---|---|
| Оставить как есть | Долг живёт, чистка не знает своего же ключа | утечка токена в лог при первой же отладке |
| Переименовать и **поднять версию формата** | Прежний файл отвергается с «сделан другой версией программы» | поход в личный кабинет за новым токеном: показывают его один раз |
| Переименовать, **мигрировать файл при чтении** | Чтение начинает уметь отказывать: носитель только для чтения, флешка, антивирус | испорченный файл токена = тот же поход в кабинет |
| Переименовать, **читать оба вида, писать новый** | Прежний файл читается как есть, формат меняется сам при замене токена | таблица прежних имён живёт в коде постоянно |

## Решение

Четвёртый вариант.

1. Имена полей: `version`, `token`, `scope`, `issued`, `account`.
2. `broker/token_store.py::LEGACY_KEYS` держит прежние имена. Чтение принимает
   оба; при совпадении обоих имён в одном файле верным считается нынешнее.
3. Запись — только нынешними именами. Файл переходит в новый вид сам, при
   следующей замене токена.
4. Версия формата **не поднята**: состав полей не изменился, а `load`
   на незнакомой версии отказывается работать целиком.
5. Чтение чужого файла его не переписывает. О прежнем формате говорится строкой
   в журнале — с именами полей и путём, без единого значения.
6. `redaction._BARE_FIELDS` держит **оба** имени и после переименования.

## Основание

Файл владельца счёта с русскими ключами лежал на диске в момент правки —
`userdata/broker-token.json`, токен «только для чтения», выпущен 04.09.2026.
После правки он прочитан без изменений: sha256 и mtime совпали, права `0600`.

Прежнее имя поля остаётся в образцах чистки **навсегда**: файлы того формата
лежат в резервных копиях папки данных, а копия папки — штатный способ перенести
портативную программу на другую машину (решение 0001).

## Что это ломает

Ничего из работающего. Программа старее 06.09.2026 не прочитает файл, записанный
новой: она не знает латинских имён. Обратная совместимость односторонняя, и это
осознанно — назад версии не откатывают.
