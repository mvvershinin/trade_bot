# 0019. «Всегда в позиции» — пять законных исключений, а не четыре

**Дата:** 04.09.2026
**Статус:** принято
**Кто решил:** владелец счёта

## Вопрос

Редакционный вопрос, не из ТЗ §10 — найден при проверке полноты `QUALITY.md` §4
(30.08–03.09.2026, `ROADMAP.md` §9). ТЗ §4.3 пишет «четыре законных исключения»
и тут же приводит таблицу из **пяти** строк: вне торгового окна; выходные и
нерабочие дни биржи; интервал паузы; сработал тейк и включён стоп на день;
достигнут дневной лимит убытка. `DOMAIN.md` §3 уже был написан по таблице и
говорит «пять». Задан прямо: верна таблица из пяти, или один из пяти лишний?

## Решение

**Верна таблица — пять случаев.** Текст ТЗ §4.3 («четыре») — недосмотр редакции,
таблица правильная. В работе не меняется ничего: `DOMAIN.md` §3 уже был написан
по таблице, а не по числу в тексте.

## Основание

Прямой ответ владельца счёта: «по таблице». Без цифры — это вопрос «какое из двух
противоречащих мест ТЗ верно», не число, измерению не подлежит.

## Что это ломает

- OPEN-QUESTIONS.md, редакционный вопрос — закрыт.
- `SPEC.md` (вне git, не правим) продолжает содержать внутреннее противоречие
  «четыре» против таблицы из пяти — это подтверждённое решение не трогать исходный
  текст ТЗ (`ROADMAP.md` §9, запись от 03.09.2026), а не забытое дело.
- Пункт приёмки «каждое исключение из „всегда в позиции“ объяснено строкой
  в журнале» (`QUALITY.md` §4) становится проверяемым буквально: искать ровно
  пять строк по пяти причинам. Шестой случай, `close == EMA` (решение 0004),
  в это число не входит — это особое поведение сигнала на границе, а не отсутствие
  в рынке, и считается отдельно.
- Ничего не меняется в `DOMAIN.md` §3, `QUALITY.md` §4 и коде: оба документа уже
  были написаны по таблице из пяти, решение задним числом подтверждает уже
  сделанный выбор.
