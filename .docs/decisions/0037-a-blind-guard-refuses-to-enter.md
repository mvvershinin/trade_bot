# 0037. Предохранитель, не знающий размера счёта, вход запрещает

**Дата:** 05.09.2026
**Статус:** принято
**Кто решил:** владелец счёта

## Вопрос

Найдено аудитом `/risk` 05.09.2026 прогоном сценария, а не чтением кода.

Два предохранителя из трёх — дневной лимит убытка и запас свободных средств —
считаются от размера счёта. Снимок счёта может не прийти: брокер не ответил,
связь оборвалась, портфель вернул незнакомый вид.

Сегодня в этом случае робот **всё равно входит**, написав в журнал
«НЕ ПРОВЕРЕНО». Для прогона по истории это верно — там счёта нет по определению.
В бою это означает «узнать о нехватке средств из отказа брокера», то есть ровно
то, ради чего предохранитель и заводился.

Решения не было ни в [`0034`](0034-volume-cap-refuses-the-order-not-trims-it.md),
ни в [`0035`](0035-account-money-is-pushed-into-the-engine.md),
ни в [`0036`](0036-margin-shortfall-cuts-to-whole-contracts.md).

## Варианты

| Вариант | Последствие |
|---|---|
| **Не входить** | Робот ждёт и не торгует, пока не узнает размер счёта. Цена: пропущенный торговый день из-за молчания брокера, а не из-за рынка |
| Входить с предупреждением | Торговый день не теряется, но предохранитель в этот момент не предохраняет, и о нехватке средств узнаём из отказа брокера |
| По-разному для двух проверок | Запас средств — не входить, дневной лимит — пускать: он про убыток за день, а не про возможность сделки |

## Решение

**Не входить.** Обе проверки при неизвестном размере счёта запрещают вход.

## Основание

Ответ владельца счёта, совпал с рекомендацией координатора. Довод рекомендации:
предохранитель, который в момент неизвестности пускает, — не предохранитель.
Цена названа честно и принята: пропущенный торговый день по технической причине.

## Следствия

1. **Это касается только боевой работы.** Прогон по истории и наблюдение
   на живом потоке размера счёта не имеют и иметь не должны — там запрет
   не применяется, иначе движок начнёт различать, откуда пришла свеча
   (главное правило, `ARCHITECTURE.md`).
2. **Отказ обязан быть виден и объяснён.** Не молчаливое бездействие, а строка
   в журнале решений человеческим языком: почему не вошли и что сделать.
3. **Снимок счёта протухает.** `broker/account.py` отдаёт `taken_at` и `fresh(now)`,
   годность снимка — две минуты. Положенный в движок снимок сегодня живёт вечно,
   «отозвать» его нечем — это отдельный долг, и без него решение работает
   наполовину: робот, однажды узнавший размер счёта, будет считать его вечным.
4. **Пятый случай «робота нет в рынке» этим не становится.** Пять законных
   исключений ([`0019`](0019-five-flat-exceptions-confirmed.md)) — про торговые
   правила; отказ по неизвестности счёта это техническая неготовность, и в журнале
   он должен читаться иначе, чем «сегодня не торгуем по правилу».
