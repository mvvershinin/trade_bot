# 0043. ГО под контракт до первого входа берётся у биржи с надбавкой

**Дата:** 05.09.2026
**Статус:** принято командой; **надбавка ждёт подтверждения владельца счёта**
**Основание:** `D-046`, поставлен `broker-expert`, поднят координатором как 🔴

## Вопрос

Замкнутый круг. Предохранитель запаса свободных средств делит свободные деньги
на ГО одного контракта. По HTTP брокер отдаёт ГО контракта **только** через
открытую позицию — `lockedForFutures / |quantity|`. Значит перед первым входом
за день числа нет, предохранитель пишет «НЕ ПРОВЕРЕНО», и так каждый день.

## Что установлено про API БКС, и это опровергает прежнюю запись

`D-046` и [`27-ws-marginal-indicators.md`](../broker-api/27-ws-marginal-indicators.md)
утверждали: «лечится полем `futuresCollateral` сервиса «Маржинальные показатели»,
а он только на вебсокете». **Это неверно.** Официальный PDF о контейнере
`futuresPortfolio` говорит дословно: «Массив данных по инструментам срочного
рынка **в портфеле**. При отсутствии позиций приходит **пустой массив**».
То есть вебсокет даёт ГО **позиции**, а не контракта, и круга не разрывает.

Пройдено оглавление PDF и все схемы. Прямого поля «ГО под контракт X» у брокера
**нет ни в одном методе**:

| где искали | что там | годится? |
|---|---|---|
| `futuresParameters.futuresPortfolio[].futuresCollateral` (WS) | ГО позиции; без позиций пустой массив | нет |
| `marginParameters.collateral` (WS) | ГО портфеля целиком | нет |
| `fortsStability.ownFunds` (WS) | деньги под ГО + свободные + вармаржа | нет |
| «Лимиты»: `cbplUsedForPositions`, `cbplUsedForOrders` | по портфелю | нет |
| Справочник инструментов | поля ГО нет вовсе | нет |
| «Получение дисконтов»: `discountLong`, `discountShort` | ставка по тикеру, **от портфеля не зависит** | **кандидат, не проверен** |

## Решение

**Источник — биржа, а не брокер.** MOEX ISS отдаёт `INITIALMARGIN` бесплатно
и без токена (поле уже читается — решение [`0041`](0041-the-cost-of-a-point-comes-from-the-exchange.md)).

Порядок по точности, и он один, в `broker/margin.py::MarginBook.best`:

1. **открытая позиция сейчас** — ответ брокера, не оценка;
2. **брокерское число из недавней позиции** (до часа) — внутри клирингового
   отрезка ГО не меняется, а торговое окно короче часа;
3. **биржевое `INITIALMARGIN` × надбавка** — оценка, помечена оценкой;
4. ничего — `None`, как было.

### Надбавка — 2,0, и ошибка направлена вверх намеренно

Замер 05.09.2026: биржа по `MXU6` — 23 124,62 ₽, брокер в окне владельца
счёта — 38 526 ₽. Надбавка 1,666. **Одно наблюдение, один инструмент, один
день**; спросить надбавку у брокера в API нечем.

Взято 2,0, потому что число обязано быть верхней границей: `floor(свободные / ГО)`
при заниженном ГО даёт лишние контракты и **отказ брокера на заявке**,
при завышенном — недобор объёма.

### Чем это платится — названо, а не спрятано

При свободных 120 000 ₽ и настоящем ГО 38 526 ₽ брокер позволил бы три
контракта, робот возьмёт два. **При свободных 40 000 ₽ брокер позволил бы один,
а робот не возьмёт ни одного и пропустит сигнал** (решение
[`0014`](0014-daily-loss-limit-and-margin-shortfall.md): не хватило на контракт —
сигнал пропускается).

### Оценка называется оценкой вслух

`AccountFunds.margin_per_contract` — это `float`, и движок отличить оценку
от ответа брокера не может по построению. Поэтому единственное место, где
владелец счёта об этом узнаёт, — строка журнала решений «Гарантийное обеспечение
под контракт» уровня «предупреждение», со словом ОЦЕНКА, с биржевым числом,
с надбавкой и с предупреждением «объём может быть занижен».

## Что меняется в поведении робота

**До:** ГО неизвестно → `affordable_volume` = «не считали» → предохранитель
молчит «НЕ ПРОВЕРЕНО» → робот входит **заданным** объёмом.
**После:** ГО оценено → предохранитель считает → объём может оказаться меньше
заданного или нулевым.

⚠️ Это торговое изменение, и оно сделано на **оценочном** числе. Владелец счёта
вправе его отменить: `BROKER_MARKUP` — одна константа в `broker/margin.py`.

## Что это НЕ закрывает

⚠️ **Надбавка не подтверждена.** Вопрос вынесен в `OPEN-QUESTIONS.md` №20.
Первый же день с открытой позицией даёт измеренное значение —
`MarginBook.markup_seen()` считает его из пары «биржевое / брокерское»,
но никуда пока не пишет.

⚠️ **Биржевое ГО как есть, без надбавки, брать нельзя** — оно на 66 % ниже
брокерского по единственному замеру. Как запасной путь годится только
в паре с надбавкой.

⚠️ **`instruments-discounts` не проверен.** Ставка × стоимость контракта дала бы
ГО прямо от брокера, но документация не утверждает, что ставка применима
к фьючерсу так, а стоимость контракта в рублях сама выводится (цена × стоимость
пункта). Две невыверенные догадки подряд для числа, которым считаются деньги, —
недопустимо. Проверяется одним запросом с токеном на чтение.

⚠️ **Живьём не проверено ничего.** Ни одного запроса с настоящим токеном.
