# 0024. Токен хранится файлом рядом с программой, системное хранилище ОС не добавляется

**Дата:** 04.09.2026
**Статус:** принято
**Кто решил:** владелец счёта

## Вопрос

Не из ТЗ §10 — вопрос добавлен из практик августа 2026 (`DESKTOP-2026.md` §4).
ТЗ требует хранить токен файлом рядом с программой. Добавлять ли вторым способом
системное хранилище секретов операционной системы: Credential Manager в Windows,
Secret Service в Linux.

## Варианты

| Вариант | Последствие |
|---|---|
| Только файл | Одинаково работает на обеих системах, переносится вместе с папкой. Токен лежит на диске, защита — права доступа и чистка логов |
| Плюс системное хранилище | Токен не лежит файлом, но привязан к машине и учётной записи: перенос программы на другой компьютер перестаёт быть копированием папки |

## Решение

**Только файл рядом с программой, как требует ТЗ.** Системное хранилище ОС
не добавляется.

## Основание

Прямой ответ владельца счёта. Довод рекомендации: единственный реальный путь
утечки — токен, попавший в git при публикации репозитория, — закрыт `.gitignore`
с якорными паттернами, а защита самого файла уже сделана с запасом и заморожена
(`BACKLOG.md`, раздел «Заморожено»): непечатаемый тип, ломающий `repr`/`str`/
`format`/`len`/`pickle`, атомарная запись с правами 0600 через tempfile и fsync,
двухрубежная чистка логов, отдельный файл тестов на утечки.

Привязка к машине вдобавок противоречит выбранной портативной поставке
([0001](0001-packaging-nuitka-portable.md)): программа задумана как папка, которую
можно перенести.

## Следствия

1. Работа по хранению токена закончена, к ней не возвращаются.
2. **Незакрытая дыра рядом остаётся открытой и от этого решения не зависит:**
   `broker/redaction.py` подключает чистку только к логгеру `broker`, а `httpx`
   и `httpcore` в списке есть, но не подключены. Поднимут `httpx` в debug при
   разборе обрыва связи — токен уйдёт в лог целиком. Закрывается вместе с выходом
   на боевой счёт, запись в `BACKLOG.md`.
