# 0001. Упаковка: Nuitka standalone, портативная поставка без установщика

**Дата:** 30.08.2026
**Статус:** принято
**Кто решил:** заказчик работ (владелец проекта)
**Отменяет:** первоначальный вариант «PyInstaller `--onedir` + установщик Inno Setup»

## Вопрос

ТЗ §6 называет PyInstaller: «собирает всё в один исполняемый файл: пользователь
не устанавливает Python и ничего не настраивает вручную». Требование — результат,
а не конкретный инструмент. Чем именно достигать результата, ТЗ не определяет жёстко.

Вопрос встал из-за антивирусов: сборки PyInstaller регулярно получают ложные
срабатывания, а [подписи кода не будет](0002-no-code-signing.md).

## Варианты

| Вариант | Антивирусы | Установка у пользователя | Время сборки |
|---|---|---|---|
| PyInstaller `--onefile` | Хуже всего: загрузчик в списках угроз + самораспаковка в `%TEMP%` | Один файл | Минуты |
| PyInstaller `--onedir` + установщик | Загрузчик остаётся в списках угроз | Setup.exe | Минуты |
| **Nuitka standalone** | Нативный бинарь, загрузчика нет | Папка, ничего не ставится | Десятки минут |

**Ключевой факт, который решил вопрос.** Ложные срабатывания на PyInstaller — не общее
свойство «упакованного Python», а свойство самого PyInstaller: у него есть загрузчик
(bootloader) — один и тот же бинарный стаб во всех сборках, попавший в списки угроз
ряда антивирусов. Плюс UPX-сжатие по умолчанию, а упаковщики — отдельный признак
для эвристик.

`--onedir` убирает только самораспаковку. Загрузчик остаётся. То есть лечит симптом.

Nuitka компилирует Python в C и линкует нативный бинарь: загрузчика нет, архива
с байткодом нет, для эвристик это обычная программа. Замеренный эффект перехода
в открытых источниках: **с 11 срабатываний из 60 до 1 из 60**.

## Решение

**Nuitka standalone** (через `pyside6-deploy` или напрямую `nuitka --standalone`).

**Поставка — портативная, установщика нет:**

| Платформа | Что получает пользователь |
|---|---|
| Windows | Папка с `Терминал.exe` и всем нужным. Копируется куда угодно, работает с флешки |
| Linux | AppImage: один файл, `chmod +x`, запуск |

**Доустанавливать нечего.** Python, Qt, pandas, httpx — всё внутри бинаря.
Требование ТЗ «пользователь не устанавливает Python и ничего не настраивает вручную»
выполняется буквально и в более сильной форме, чем через установщик: не устанавливается
вообще ничего.

**Базу и папку данных программа создаёт сама при первом запуске** — это код программы,
а не внешний скрипт. Скрипт, который можно забыть запустить, — лишняя точка отказа.

**PyInstaller остаётся рабочим запасным путём.** Рабочий `.spec` поддерживается
и проверяется в CI: у Nuitka бывали регрессии между версиями (собиралось на 1.86,
ломалось на 1.9–2.01), и вторая нога стоит примерно час работы.

## Основание

- Подписи кода не будет ([решение 0002](0002-no-code-signing.md)) → антивирус остаётся
  единственным барьером между заказчиком и предупреждением при запуске
- Qt официально рекомендует `pyside6-deploy` (обёртка над Nuitka) как основной путь
  развёртывания для PySide6
- Nuitka под Apache 2.0, коммерческое использование бесплатно.
  Nuitka Commercial — опциональная подписка для защиты кода, нам не нужна
- Портативная поставка снимает необходимость в установщике целиком

## Цена решения и чем она закрывается

| Цена | Чем закрывается |
|---|---|
| Сборка идёт десятки минут на Qt-проекте | Платится в CI раз на релиз. Разработчик запускает из исходников |
| Бывали регрессии между версиями Nuitka | Версия Nuitka **жёстко зафиксирована** в lock-файле. Обновление — отдельная задача с прогоном |
| Поломки Qt-плагинов труднее разбирать: пустое окно, падение на старте | Обязательный прогон на чистой машине под обе ОС до релиза |
| На Windows сборка через MSVC тянет VC++ Redistributable | Собирать `--mingw64`: бинарь самодостаточен |

## Что это ломает

- Формулировка ТЗ §6 «PyInstaller» перестаёт описывать основной путь сборки.
  Заказчику проговаривается: результат тот же и даже лучше — программа вообще
  не устанавливается, — а инструмент выбран под отсутствие подписи.
- Раздела «установщик» в работах больше нет. Вместо него — сборка портативной папки,
  AppImage и создание базы при первом запуске.
- `--onefile` не используется **ни у одного** сборщика: у Nuitka он тоже
  самораспаковывается и возвращает часть проблемы с эвристиками.
