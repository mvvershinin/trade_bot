# 0003. Место рантайм-данных: одна папка `userdata/` рядом с программой

**Дата:** 30.08.2026
**Статус:** принято
**Кто решил:** команда — по итогу аудита безопасности перед первым коммитом

## Вопрос

Где программа хранит то, что создаёт сама: файл-базу со свечами и журналами,
технический лог, файл настроек с токеном брокера, экспорт отчётов.

Вопрос выглядит как оформительский, но это вопрос защиты токена. Токен — доступ
к счёту на срок до 90 дней, и рабочая копия проекта лежит в git. Пока место
не выбрано, `.gitignore` вынужден угадывать имя файла, которого ещё никто не придумал.

## Варианты

| Вариант | Последствие | Цена вопроса |
|---|---|---|
| Файлы рассыпаны в корне рядом с программой | `.gitignore` угадывает имена: `settings.json`, `config.ini`, `auth.json`, `terminal.ini`, `state.json` — проверено, **ни одно не закрыто**. Промах = токен в истории репозитория | Утечка доступа к счёту |
| Широкие правила по подстроке (`*token*`, `*secret*`) | Закрывают угаданные имена и заодно **глотают продуктовый код**. Проверено `git check-ignore`: `broker/token_store.py`, `ui/token_dialog.py`, `tests/test_token_refresh.py`, `app/credential_vault.py`, `.docs/TOKEN.md` — все молча не попадают в git | Хуже первого: предохранитель уезжает в сборку с диска разработчика, минуя ревью и историю. Обнаруживается в свежем клоне, когда чинить поздно |
| **Одна папка `userdata/`, закрытая якорным правилом** | Правило одно, привязано к месту, а не к имени. Имена файлов внутри выбираются свободно и ничего не ломают | Требует, чтобы код с самого начала складывал файлы туда |

## Решение

Всё, что программа создаёт сама, живёт в папке **`userdata/`**. Папка целиком
закрыта якорным правилом `/userdata/` в `.gitignore`.

### Где именно эта папка — по способу запуска

Наивное «рядом с исполняемым файлом» в поставке из [решения 0001](0001-packaging-nuitka-portable.md)
**не работает**, и отказ будет тихим и дорогим:

| Запуск | Якорь | Почему не иначе |
|---|---|---|
| AppImage (Linux) | переменная окружения `APPIMAGE` — абсолютный путь самого файла `.AppImage` | AppImage монтирует свой образ **только на чтение** и запускает программу изнутри монтирования. `__file__` и `sys.executable` указывают внутрь него: `mkdir` даст «read-only file system». `APPDIR` — то самое монтирование, брать его нельзя |
| Портатив Nuitka (Windows) | каталог `sys.executable` | Модули слинкованы в бинарь, `__file__` каталога поставки не даёт |
| Из исходников | корень рабочей копии | `python3 -m app.main`, ARCHITECTURE.md §2 |

⚠️ **Худший исход — не падение, а молчаливая потеря.** Если путь уедет на временную
файловую систему, файл токена, база свечей и оба журнала стираются при выходе:
владелец счёта вводит 90-дневный токен заново при каждом запуске, история
перекачивается заново, журнал сделок за день исчезает. Поэтому при старте
выполняется проба на запись, а запасной вариант выбирается **видимо** —
строкой в журнале и сообщением в окне, а не молча.

То же на Windows: папка, распакованная в `Program Files`, не пишется, и виртуализации
файлов для 64-битного процесса нет — будет отказ в правах.

Правила по подстроке (`token`, `secret`, `credential`) остаются как второй рубеж,
но **только якорные, на корень рабочей копии**. Правила по расширению
(`*.pem`, `*.key`, `*.p12`, `*.pfx`, `*.dmp`) действуют на любой глубине: расширение
продуктовый код не глотает.

## Основание

Аудит поверхности утечки перед первым коммитом, 30.08.2026. Оба провальных
варианта проверены прогоном `git check-ignore`, а не рассуждением: первый пропускает
пять правдоподобных имён файла настроек, второй прячет шесть путей продуктового кода.

## Что это ломает

- `ARCHITECTURE.md` §7 говорит «всё рядом с программой». Уточняется: **в одной папке**
  рядом с программой. Резервная копия и перенос по-прежнему делаются копированием,
  но копируется папка программы вместе с `userdata/`. Для AppImage копируемых
  объектов два: сам файл `.AppImage` и папка `userdata/` рядом с ним.
- Токен по-прежнему **не попадает** в технический лог, журналы, экспорт отчётов
  и резервные копии — кроме своего файла. Общая папка этого не отменяет.
- Права на файл токена (0600 / ACL по ТЗ §4.1) выставляет код, а не расположение.
  Папка защищает от git, не от чужого пользователя в системе.
- Решение **не закрывает** открытый вопрос о системном хранилище ОС
  (Credential Manager / Secret Service) — см. [`../OPEN-QUESTIONS.md`](../OPEN-QUESTIONS.md).
  Оно фиксирует основную ветку по ТЗ §4.1 — файл рядом с программой — и место,
  где этот файл лежит.
