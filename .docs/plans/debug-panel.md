# Панель «Отладка»: живая лента событий робота

**Дата:** 12.10.2026 · **Кто:** `desktop-ui-expert`, фаза 1 из 4 (миниплан) · **Просьба:** владелец счёта 12.10.2026

## Чья боль

Между строками журнала решений владельцу не видно, пришла ли минута, закрылся ли бар, что движок увидел и почему промолчал. Нужно так: открыл кнопкой, посмотрел, свернул.

## Решения

| Вопрос | Решение |
|---|---|
| Транспорт | **`logging`, второй ленты нет.** Новый логгер `app.panel` (`propagate=False`) — только для строк, которых сегодня нет нигде. Обработчик `PanelHandler` (`app/debug_feed.py`) висит на нём и на корне, поэтому техлог INFO+ приходит в ленту сам. Строки журнала программы попадают в ленту одной строкой лога внутри `HistoryPort.note` — это единственный их выход (`port.py:2741`). На сигналы порта окно не подписывается: при пересчёте `decisions_replaced` приносит журнал целиком, и пришлось бы вычислять разницу, то есть заводить второй подсчёт |
| Граница потоков | `emit` работает в любом потоке, в том числе в потоке данных (`_load_tick`, `market/`). Он кладёт готовую строку с номером в `deque(maxlen)` под замком обработчика. Окно забирает строки с номерами больше последнего виденного: по `QTimer` раз в 250 мс, только пока панель открыта, не больше 1000 за раз. Сигналов на каждую строку нет |
| Чистка | **Рубеж 1** — `emit`: `scrub` по готовому тексту и по первой строке исключения, то есть та же функция, что у `RedactingFormatter`. `handleError` молчит, как `TechnicalLog.handleError`. **Рубеж 2** — «Скопировать» прогоняет текст через `sanitize` окна (`ui/ports.py::Sanitize`). В `ui/` приходят уже чистые `DebugLine`, `broker/` окно не импортирует |
| Что уходит в файл | **Ничего нового.** `app.panel` до корня не доходит по построению. Строка «минута …: оборот → контракты» (`live_feed.py:1409`) остаётся в файле как есть; в ленту она не идёт (`extra={"panel": False}`), потому что её числа уже есть в строке ленты. Прирост `terminal.log` — 0 строк в день, расчёт ротации в шапке `app/logs.py` остаётся верным |
| Чужие логгеры | Из `httpx`, `httpcore`, `websockets` (`FOREIGN_LOGGERS`) в ленту попадает только WARNING и выше. В сегодняшнем `terminal.log` строк `httpx` 1816 из 4900 |
| Время | `datetime.fromtimestamp(record.created, MSK)`. `created` — секунды эпохи, а `asctime` в файле печатается в поясе машины (+7). В шапке панели — «время МСК» |
| Буфер | **5000 строк.** Вживую ожидается 2–3 строки в минуту: начало и закрытие минуты, бар раз в 5 минут, его решения. Сеанс в 830 минут даёт примерно 2100–2500 строк, то есть в буфер помещаются два торговых дня. Память — не больше ~5 МБ. Вытесненные строки считаются, а при открытии панели первой строкой стоит «вытеснено N» |
| Пересчёт | Бары фазы «пересчёт» отдельных строк не дают: в конце (`observe.py:565`) выводится одна строка-итог — баров, с какого по какое время, строк журнала, заявок, сделок, сколько секунд. Для прогона по истории при выключенном потоке такая строка уже есть: «Прогон по истории» (`port.py:4189`) |
| Где в окне | `QDockWidget` у нижнего края. Его можно только закрыть: отрыва и переноса нет. При запуске он свёрнут. Кнопка «Отладка ▴/▾» постоянно стоит в строке состояния слева от часов, прямо под панелью. Состояние кнопки берётся из `visibilityChanged` дока. Кнопка «Развернуть график» на панель не влияет: та обнуляет только разделитель. График и журналы не меняются — изоляция графика сохраняется. Внутри дока — `QListView` с моделью, цвет строки модель берёт из текущей темы в `data()`. «Очистить» очищает окно, а не буфер. «Скопировать» берёт выделенное, а если ничего не выделено — всё |

| Минута растёт | уходит только в график (`live_feed.py:1389`) | строка на **первом** принятом снимке минуты, в `_accept` |

| Заявки, исполнения, касания | срез исполнителя (`observe.py:746`) идёт только в базу | строка на каждую запись того же среза |

| Ход открыт или закрыт | `observe.py:505` и `:571`, только журнал прогонов | строки в `start` и `aclose` |
| «Применить» | `_apply` → `note` (`port.py:3006`) | уже есть |
| Поток подключился или оборвался | лог (`live_feed.py:1197`, `:1225`) и `say` | уже есть |
| Догрузка | `_tell` → `note` (`backfill.py:1180`), лог `:996` | уже есть |
| Загрузка истории | `note` при начале и конце (`port.py:2020`, `:2671`) | начало и конец уже есть; ход по страницам остаётся в полоске прогресса |
| Отказы и ошибки | `note(WARNING)` (`port.py:3010`, `:3194`), `log.exception` ×30 | уже есть; цвет строки зависит от уровня |

**Без правки движка не получить:** (1) слова стратегии на «тихом» баре. Движок пишет причину только при её смене, а `Outcome` не несёт `Decision`, поэтому лента покажет числа и шаг разбора, но не слова «почему». (2) Решения по каждому бару прогона по истории: этот цикл живёт в `backtest/history.py:888`, а не в `app/`, — будет только итог.

## Что может сломаться и как это обнаружится

| Поломка | Сторож — и какая мутация его роняет |
|---|---|
| Пересчёт заваливает окно тысячами строк | ход на 5000 барах даёт ровно 1 строку итога. Роняет мутация «убрать проверку фазы» |
| Отладочная строка роняет живой ход (исключение в `_walk` превращается в «Живой ход прекращён») | сборщик строки заменён на бросающий исключение → `run.halted` остаётся пустым, бары идут дальше. Роняет мутация «снять защиту» |
| Токен проходит мимо чистки: аргументы, исключение, `note`, копирование | отметка из реестра `redaction.remember` в четырёх путях не попадает ни в ленту, ни в буфер обмена. Роняет мутация «`scrub` убран из `emit`» |
| Частые строки съедают ротацию файла | 1000 строк `app.panel` при включённом `TechnicalLog` во временной папке — их нет в файле. Роняет мутация `propagate=True` |
| Отказ доходит без цвета или не доходит вовсе | `_refuse` даёт в ленте строку WARNING с цветом `theme.warning`, ERROR — с `danger`. Роняют **мутация молчания** (убрать лог из `note`) и мутация «WARNING → INFO» |
| Буфер растёт | после N+500 строк: длина N, «вытеснено 500», в модели строк не больше N. Роняет `maxlen=None` |
| Автопрокрутка борется с человеком | прокрутили вверх → новые строки и вытеснение сверху не сдвигают видимую строку; внизу → лента идёт за новыми. Роняет «всегда `scrollToBottom`» и «без поправки на вытеснение» |
| Время в поясе машины | `TZ=Asia/Novosibirsk` + `tzset`, `created` = 07:00 UTC → в ленте 10:00. Роняет мутация `localtime`. На Windows `tzset` нет — там тест пропускается |
| Пока панель скрыта, строки теряются | панель скрыта, пришло 10 строк, панель показали → видно 10 строк. Роняет «опрос, выбрасывающий строки при скрытой панели» |
| Смена темы не перекрашивает | `MainWindow` переключили с тёмной темы на светлую → цвет строки и фон меняются на цвета новой темы. Роняет удаление вызова `set_theme` из `apply_theme` |
| Док закрыли крестиком, а кнопка осталась «▴» | `dock.close()` → кнопка не нажата и показывает «▾». Роняет отключение `visibilityChanged` |
| Двойная установка даёт дубли (`setup_logging` вызывается дважды) | установить два раза → на одну запись одна строка |
| Обработчик переживает тест и течёт в соседние (правило 14) | фикстура снимает обработчик; каждый тест прогоняется в одиночку |
| Лента выдумывает решение, которого не было («вторая правда») | **пусто:** слова «сигнал» и «вход» берутся только из журнала движка, а строка бара содержит только числа и поля `Outcome`. Это ловит только ревью |
| Свёртка «пересчёт → итог» прячет ошибку пересчёта | **частично пусто:** WARNING и ERROR, случившиеся при пересчёте, идут через `note` или техлог мимо свёртки. Проверяется одним тестом с отказом исполнителя при пересчёте |

## Что решение не закрывает

* Слова стратегии на «тихом» баре и пошаговые решения прогона по истории — см. опись.
* Источник бара: у `market.Candle` нет поля источника (`market/candles.py`), и бар, собранный из догруженных минут, лента от бара живого потока не отличит.
* Ход загрузки истории по страницам, строки `httpx` и HTTP уровня INFO, число принятых снимков за минуту.
* Строки ленты не переживают перезапуск и не пишутся в файл. Решения и заявки хода уже лежат в базе (`app/paper_log.py`).
* Выгрузки в файл, поиска, фильтра по типу, отрыва панели в отдельное окно и запоминания «открыта/свёрнута» нет.
* Перебор параметров идёт в отдельных процессах, его строки в ленту не попадают.
* Вживую на Windows и Wayland не проверялось.

## Поправки гейта `code-critic` (внесены до кода)

1. Исполнения и закрытые сделки симуляции: свои курсоры `seen_fills` и `seen_deals` в `_Tally`, строка на каждое в `_note_orders` (кроме фазы «пересчёт»).
2. Строку ленты собирает одна точка входа `app/debug_feed.py`: построители под общей защитой, исключение не уходит наружу ни в `_accept`/`_close_minute`, ни в `_draw_live`, ни в `_walk`. В `_draw_live` строка стоит после `refresh`. Сторожа на все три пути.
3. Пойманный отказ сборки: первый — одна строка WARNING (в файл и в ленту), дальше только счёт; число «не собрано» — в шапке панели. Отказ обработчика ленты (`handleError`) только считается. В обычной работе прирост файла — 0.
4. Близнецы «лог + журнал об одном событии» помечаются `extra={"panel": False}`: `live_feed` (снятие потока, расписание ×2, обрыв, опрос счёта ×2, сборка подключения), `backfill`, `halt`, `paper_log` ×2, `observe` (ход прекращён), `port` (контракты ×2, прогон, запись остановки), `main` ×2. Сторож: одна строка на событие.
5. `app.panel`: `propagate=False` ставится при импорте вместе с `NullHandler`; `logging.lastResort` недостижим. Сторож.
6. `debug_feed.uninstall()` снимает обработчик с корня и с `app.panel` и обнуляет счёт; зовёт его общая фикстура `pristine_logging`. `close_logging` ленту не трогает: её снимал бы повторный `setup_logging`.
7. OHLC закрытого бара — только из свечи, которую получил движок (`_walk`). В `_draw_live` — строка без цен: «минуты бара собраны, пересчёт поставлен».
8. Добавлено в «не закрывает»: у `market.Candle` нет поля источника, бар из догруженных минут не отличить.
9. Сторож «пересчёт → итог» считает и строку прогрева (`_say_warmup`), данные — с заявками; сделок в итоге — `run.summary.trades`; отметка «вытеснено N» ставится между старыми и новыми строками при каждом чтении с разрывом; уровень обработчика INFO явно; `app/debug_feed.py` не импортирует `ui.ports` и PySide6 (сторож подпроцессом).

## Проверка

Сторожа и мутации — в таблице выше, файл `tests/test_debug_panel.py`. Мутации прогоняет `test-expert`, а не автор. Пределы: `MainWindow.__init__` стоит на 75 строках, `_pass` и `_walk` к пределу близки, поэтому добавки уходят в помощники. **На пути человека:** в будний день в торговые часы запустить программу из исходников на **копии** `userdata` в отдельной папке; процесс и папку владельца не трогать. Включить поток, открыть панель, дождаться закрытия 5-минутного бара: должны появиться минуты, бар, решение и заявки. Затем свернуть и развернуть панель, сменить тему, нажать «Скопировать» и вставить текст в редактор. Снимки обеих тем посмотреть глазами. Сравнить число строк `terminal.log` копии за час по логгерам до и после правки: должно совпасть.
