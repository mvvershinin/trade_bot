# Миниплан. Скользящий уровень едет внутри пятиминутки + журнал различает вид уровня

**Задача:** З7 фаза В (В4, В5, В7) и Г5, [`E5-module-2-implementation.md`](E5-module-2-implementation.md).
**Основание:** решения [0059](../decisions/0059-two-watched-levels-and-a-level-that-moves-inside-the-bar.md) §3,
[0060](../decisions/0060-customer-answers-on-the-second-algorithm-settings.md) §2. Писал `strategy-quant` 29.09.2026.

## 1. Откуда внутрибарная цена — правило 1 не нарушается

Лучшую достигнутую цену **сообщает исполнитель** (0059 §3), движок её не наблюдает.
Минутки идут в `HistoryExecutor` через `replay(..., minutes=...)`; `HistorySource`
и `engine/` минуток не видят. Исполнитель обходит точки минуток под текущей
пятиминуткой в заданном порядке и, когда экстремум в пользу позиции обновился,
отдаёт в существующем круге обмена `fills_at` **не сделку, а наблюдение**
(`PriceSeen`: время, цена). Движок пересчитывает уровень той же арифметикой
`TakeProfit.advance` и подаёт `ARM`; исполнитель продолжает обход со своего курсора.
В бою адаптер отдаёт то же наблюдение по тикам потока тем же вызовом.
Движок не знает, минутка это или тик.

**Отвергнуто:** незакрытые пятиминутки через источник — движок получил бы бары
с бегущими `high`/`low`, прогон делал бы в 20 раз больше вызовов движка (`sweep`,
`leaders`), а касание по накопленному размаху после сдвига уровня ложно.

Правила обхода:
- касание проверяется **по отрезку между соседними точками**, а не по размаху
  минутки или бара; `_reachable` — по размаху минутки;
- `Fill.at` остаётся началом пятиминутки: путь Б «стопа после тейка» берёт дату отсюда;
- точка, давшая новую вершину, новый уровень задеть не может (уровень позади цены
  на отступ) — порядок «проверка касания / сдвиг» внутри точки на сделки не влияет;
- кругов обмена на бар: до 20 наблюдений + 2 ≤ `_MAX_ROUNDS = 64`; шаг подтяжки режет ещё.

## 2. Что меняется

| Файл | Что |
|---|---|
| `engine/contracts.py` | `ExitReason.TRAILING_TAKE` «скользящий уровень»; тип `PriceSeen` |
| `engine/ports.py` | контракт `fills_at`: наблюдение цены — законный элемент ответа, частота, порядок |
| `engine/pipeline.py` | `_closed`: причина по `position.take.trailing`; разбор наблюдения — **через `advance`**, строка журнала при сдвиге |
| `engine/runner.py` | `_exchange` различает сделку и наблюдение |
| `backtest/execution.py` | курсор по точкам минуток, касание по отрезку, выдача наблюдений |
| `backtest/history.py` | `replay(minutes=)`; `:507`, `:539` — причина из заявки, не жёстко `TAKE_PROFIT` |
| `backtest/assumptions.py` | допущение «порядок обхода цен минутки»; `:211` считает оба вида уровня |
| `backtest/stitched.py` | минутки по куску |

**Порядок обхода — допущение прогона, а не `EngineSettings`** (минутки есть только
в истории). Живёт рядом с проскальзыванием: `ui/models.py` → `convert.run_costs` → `replay`.
Временное значение «открытие → ближний к открытию экстремум → дальний → закрытие»;
при равном удалении — сначала неблагоприятный для позиции; плоская минутка — одна точка.

**В5 — шаг подтяжки уже настройка** (`engine/settings.py:223`, `ui/models.py:1003`,
`app/runs.py:240`), заново не заводится. Частота: сдвиг только при уходе кандидата
на шаг, значит не больше движения цены за бар / (цена × шаг %); предел брокера
открыт (`B-017`), из памяти не берётся.

**В7:** линия уровня на графике получает точки внутри бара из журнала наблюдений прогона.

## 3. Первый алгоритм нетронут — две стены

1. Сверка **127/127** при прежних настройках — после каждого шага, локально.
   Слабость: сверка зовёт `replay` без минуток и зелена при любом новом коде.
2. **Вторая стена:** неподвижный тейк + поданные минутки = тот же список сделок
   **и то же число `ARM` (517 на 127)**, что без минуток. Держится на первой строке
   `advance` (`if not self.trailing`) — наблюдение обязано идти через неё.
   Минуток за период сверки в `reference/` может не быть — тогда на реальном
   периоде локальной базы, с минутками и без.

## 4. Поля окна (правило 16) — только порядок обхода

Поле «Порядок проверки цен минутки» (выбор из двух: ближний экстремум первым /
неблагоприятный первым), подпись, проверка значения, строка в журнале изменений
настроек, ключ в снимке прогона (`app/runs.py`), вопрос 25 в `OPEN-QUESTIONS.md`.

## 5. Сторожа и мутации (ломает `test-expert`)

| Поведение | Мутация, обязанная ронять |
|---|---|
| порядок берётся из настройки | зашить порядок в код |
| касание по отрезку | проверять накопленный размах после сдвига |
| неподвижный тейк наблюдений не читает | слать наблюдение при `trailing=False` — меняется счёт `ARM` |
| уровень не едет назад внутри бара | принять наблюдение хуже вершины |
| журнал различает вид уровня | одна причина на оба |
| причина — из заявки движка | исполнитель пишет `TAKE_PROFIT` жёстко |
| прогон из окна идёт с минутками | `app/port.py` зовёт `replay` без `minutes` |
| движок не читает `high`/`low` | свеча с отравленными `high`/`low` — поведенческий сторож |

   старые прогоны обязаны читаться. Сверка.

3. Модель исполнения по минуткам (`strategy-quant`). Сверка + вторая стена.
4. Допущение и поле окна (`desktop-ui-expert`), снимок прогона.
5. Проводка: все вызовы `replay` — `app/port.py:3750`, `backtest/stitched.py:263`,

   названо поимённо; `app/port.py` — одна строка, запрос минуток отдельной функцией.
   **После** слияния параллельной работы по `app/port.py`.
