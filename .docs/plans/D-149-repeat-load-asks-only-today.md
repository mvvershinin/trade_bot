# D-149 — повторная «Догрузить» ходит на биржу только за сегодняшним днём

**1. Чья боль.** Владелец счёта после полной загрузки с 17.06 жмёт «Догрузить», и
каждый раз биржа заново отдаёт 6 прошлых дней — 3411 свечей (копия 11.10). Отметку
эти дни не получат никогда. Замер: `.docs/data/data-expert-2026-10-11-1430.md`.

**Решение.** «Отметку ставит `check_days`» отвергнуто: дневной объём ISS не сходится
с минутным ни в одном из 86 дней, `end` всегда 23:59:59, а у субботы и воскресенья
дневной свечи нет даже при торгах. Остаётся доказательство из `_covered_days`:
поток минут прошёл дальше дня. Запрос дотягивается до места, где поток пройдёт:
- а) цепочка неотмеченных дней — по ближайший более поздний день с минутами в базе
  в пределах `[since, until]` (MXU6 14.08–16.08 → по 17.08);
- б) цепочка до `until` закрытого контракта — по `last_trade_day`, не дальше сегодня
  (`sync_minutes(proof_until=)` от `load_contract_minutes`);
- дни-доказательства дописываются к **последнему куску** цепочки, а не к цепочке
  до нарезки: при длине, кратной 30 (MXU6 19.06–16.09), 17.09 ушёл бы один в свой
  кусок, и `_settle_tails` искал бы его в базе, где его нет по 0061. Их минуты
  только в счёт покрытия: в базу не пишутся, дни не отмечаются;
- в) данные куска кончились раньше его конца — следующий кусок той же цепочки
  начинается с `broke_off`, его конец не сдвигается. Кусок, начатый с переданного
  дня и оборвавшийся на нём же, дальше не передаётся: без зацикливания;
- г) **только для запросов-доказательств** (дни за концом или переданный день):
  отметка — только если в ответе есть свеча более позднего дня. Пустой ответ
  не отмечает ничего. Доверие короткому пустому куску и прогрев не меняются.
  Довод — сортировка ISS по времени, а не `IssPagingError`: тот сравнивает только
  первую минуту страницы (`iss.py:765-772`);
- отчёт: `ranges` — загружаемые дни, `proofs` — дни-доказательства, `proof_candles`
  — их свечи, не записанные. «Запрошено X из Y» считает загружаемые дни без
  повторов, дни-доказательства — отдельной фразой. «Будет перезапрошен» не пишется
  про переданный следующему куску день и про день-доказательство.

Правятся `market/sync.py`, `market/reports.py`, `market/contracts.py`,
`app/contract_view.py` и тесты. API хранилища хватает, новых чисел нет.

**2–3. Что сломается → чем обнаружено**
1. Пустой или оборванный ответ-доказательство отмечает дни — тест (Б).
2. Минуты или отметки позже `until` в базе, доказательство дальше `last_trade_day` —
   сторож вместо `max(till) == last`; у стенда свой последний день у каждого кода.
3. Каждое нажатие тянет прошлые дни — тест (А): вторая загрузка спрашивает только сегодня.
4. День-доказательство в отдельном куске (90 дней) и кусок пт–вс (`chunk_days=3`) — (Г).
5. Будний день с объёмом без минут отмечен — тест (В), прежние B1 не ослабляются.
6. Сверки дней в `test_market_sync.py` и `test_ui_contract_load.py` (976, 1017,
   1036–1038) правятся по смыслу. `test_app_backfill.py` не затрагивается: догрузка
   ходит через `fetch_minutes`. Упадёт — находка, а не правка теста.
7. Прогон: отметка закрывает последний бар дня. На M5 изменений 0 — только для четырёх
   замеренных дней. На M15 и H1 +1 бар в конце дня: MXM6 17.06 и MXU6 16.09 — на стыке,
   цена стыка сдвигается; MXU6 14.08 — **не стык**: лишний бар входит в среднюю перед
   17.08, и сделки M15/H1 могут измениться посреди куска. Не обнаружено ничем: образец
   читает минуты из `reference/`.

**4. Что НЕ закрывает**
- Сегодня торгов ещё не было — последний торговый день перезапрашивается до первой
  минуты следующей сессии, ≤ ~1000 свечей.
- `active_to == last_trade_day` либо `last_trade_day = None` — доказательства нет.
- Рубеж раньше экспирации на несколько дней — доказательство тянет их все.
- Настоящая дыра после сверки B-069 — каждое нажатие спрашивает её плюс следующий
  день, и это верно.
- Прежний остаточный риск `_settle_tails`, неполный день и торги выходного дня без минут.

**5. Как проверено.** `ruff`, `mypy`, полный `pytest`. Мутации — `test-expert`.
