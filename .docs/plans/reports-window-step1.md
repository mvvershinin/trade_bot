# Окно «Отчёты», шаг 1 — по прогону на экране (Н5, выпуск 0.2.3)

**Что видно человеку.** Кнопка «Отчёты…» в углу журналов, рядом с «Выгрузить оба журнала…».
Окно: заголовок «Отчёт по прогону на истории, <инструмент>, <первая>—<последняя свеча> МСК»,
период (кнопки «Сегодня / Неделя / Месяц / Всё» и две даты с календарём, при открытии —
текущий месяц МСК), итог тремя строками (до комиссии, комиссия, чистый) + сделок,
прибыльных, убыточных; таблица позиций; под ней — разбор выбранной строки.
Двойной щелчок — график переходит к сделке.

**Откуда данные.** `ShownRun`: строки и итог журнала «Сделки» + инструмент и свечи графика —
то, что порт уже прислал окну. Не `BacktestReport`: прогон при запуске программы его
не шлёт, и окно сказало бы «прогона нет» над сотней сделок на экране.
Сохранённых сделок симуляции нет — шаг 2 (`D-027`).

**Числа.** Итог — `span_totals` (`ui/chart_panel.py`), уже сверенный с `backtest.summarise`.
Убыточные — `< 0` по тому же столбику. Пункты — `Deal.points` / `StoredTrade.points`
полем `TradeRow.profit_points`. Разбор — `trade_lines` из «Разбора сделок» по ПКМ.

**Правило периода.** Сделка в периоде, если **дата выхода по МСК** в [с; по] включительно.

**Файлы.** Новый `ui/reports_dialog.py`; `ui/journals.py` (кнопка); `ui/main_window.py`;
`ui/chart/protocol.py`, `painter_surface.py`, `chart_panel.py` — `show_moment`;
`ui/models.py` (поле), `app/convert.py` (две строки).

**Что способно сломаться и чем поймаем** (`tests/test_ui_reports.py`).
✅ итог периода ≠ сумме строк; «Всё» ≠ итогу журнала — две проверки;
✅ сделка через полночь не в том месяце — вход 30.09, выход 01.10 → октябрь;
✅ разбор ≠ ПКМ — блок разбора графика строка в строку;
✅ пустой период / нет прогона — молча пустая таблица (правило 13);
✅ сделки нет на графике — `show_moment` даёт «нет», окно говорит словами.
