# `D-080`, код программы. «Данных нет» — плашкой при запуске

**Дата:** 11.10.2026 · **Кто:** `ui-expert` по заданию координатора · **Решение:** [0064](../decisions/0064-data-stays-next-to-the-program-update-by-unpacking-over.md)

## Чья боль

Владелец счёта обновил программу заменой папки или распаковал новую версию не туда — и видит
пустой график без единого слова. Свечи, настройки и ключ лежат в прежней папке и возвращаются
копированием, но сказать ему об этом некому (правило 13).

## Что делаем

1. **Признак** — `app/userdata_notice.py`, чистая функция от пути базы: текст или пусто.
   Данные есть, если существует хоть одно — сама база (`database.exists()`, не имя по умолчанию:
   при `--db` оно другое), `settings.json`, файл ключа. Имена — константы владельцев.
   Только `Path.exists()`: файл ключа не открывается (правило 7). `logs/`, `instance.lock`,
   `.write-probe` признаком не являются — их заводят раньше `_run`.
2. **Снимок** — в `_run` **до** `_stored_settings`: чтение настроек переименовывает испорченный
   файл, и снимок после него сказал бы «данных нет» человеку, у которого они есть.
3. **Три канала:** плашка над графиком (без крестика, цвет `warning`, перекрашивается при смене
   темы, висит весь сеанс), строка журнала решений «Папка данных» (INFO), строка техлога.
4. Пределы: `_run` и `MainWindow.__init__` стоят ровно на 75 строках — добавка компенсируется
   помощниками, не ростом.

## Что способно сломаться и чем обнаружится

| Поломка | Сторож |
|---|---|
| Плашки нет на пустой папке (молчание) | сборка программы на пустой папке: плашка видима, путь в тексте |
| Плашка на папке с данными (ложная тревога) | по одному файлу — база / настройки / ключ: плашки нет |
| Снимок после чтения настроек | испорченный `settings.json`: плашки нет |
| `--db` в другой папке — проверена не та | путь в тексте — папка из ключа |
| Содержимое ключа утекло в текст | поддельный ключ с маркером: маркера нет ни в плашке, ни в журнале |
| Плашка в цветах прежней темы | смена палитры: цвет новой темы в стиле плашки |

## Что не закрывает

* Плашка надёжна на **первом** запуске в папке: этот же запуск заводит базу (уточнение
  контрактов), и в той же папке дальше плашки нет, даже если данные так и не скопировали.
* Частичный перенос (есть база, нет ключа) — плашки нет по определению владельца.
* При `--db` в папке не с именем `userdata` путь назначения неверен (только разработчик).
* Консольные ветки `--fetch`, `--runs`, `--inspect` не предупреждают.
* Windows вживую не проверяется.
