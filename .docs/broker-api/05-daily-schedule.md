URL: https://trade-api.bcs.ru/http/information/get-daily-schedule

```
GET
## https://be.broker.ru/trade-api-information-service /api/v1/trading-schedule/daily-schedule
```

так эта страница выглядела при снятии снимка. Официальный PDF
`https://cdn.bcs.ru/static/bcs/files/trade-api-docs.pdf` называет

1. **соседний метод того же контроллера.** Статус торгов

   источниках. Двум методам одного контроллера `trading-schedule` жить
   на разных сервисах неоткуда;
2. **PDF внутренне согласован.** В нём `trade-api-bff-portfolio` встречается
   ровно один раз — у `/api/v1/portfolio`. Похоже, что в снимок имя попало
   с соседней страницы портфеля;
3. **проверить снаружи нечем.** Одностраничная документация таблицу с хостом
   не отдаёт: проверено запросом 05.09.2026, ответ — только путь без хоста.
   Ровно так же ничего не нашлось для свечей, и там верным оказался PDF.

⛔ **Живым запросом не проверено ни одно из двух имён.** Цена ошибки ограничена
намеренно: адрес стоит в `session.ADDRESS_SENSITIVE`, и 404 без кода отказа
брокера гасит метод на сеанс с одной строкой владельцу счёта.

Получить расписание на день

## Request — Query Parameters

**classCode** string **required** — Код класса ценной бумаги. **Example:** `TQBR`
**ticker** string **required** — Тикер инструмента. **Example:** `SBER`

Оба — `non-empty`.

## Responses — 200 OK, application/json

**isWorkDay** boolean Признак рабочего дня

⚠️ **PDF называет это поле `isWorkingDay`** («Признак рабочего дня
(TRUE/FALSE)»), сайт — `isWorkDay`. Какое приходит на самом деле, живым
запросом не проверено, поэтому `broker/schedule.py` читает **оба** написания.
Формулировка PDF «(TRUE/FALSE)» допускает и строку, а не только логическое
значение, — строка тоже читается.

**dailySchedule** object[] Полное дневное расписание

* **startDate** string Время начала. **Example:** `14:30:00`
* **endDate** string Время окончания. **Example:** `14:30:00`
* **tradingSessionType** string Название текущей сессии
  **Possible values:** [ `Технический перерыв QUIK` , `Аукцион открытия` ,
  `Не рабочее время/Выходной/Праздник` , `Вечерняя торговая сессия` ,
  `Торговый период` , `Аукцион закрытия` ]
* **tradingSessionStatus** string Статус сессии — [ `OPEN` , `CLOSE` ]

```json
{
  "isWorkDay": true,
  "dailySchedule": [
    {
      "startDate": "14:30:00",
      "endDate": "14:30:00",
      "tradingSessionType": "Технический перерыв QUIK",
      "tradingSessionStatus": "OPEN"
    }
  ]
}
```

## Зачем это нам — важнее, чем кажется

Это **машинный ответ на вопрос «сегодня биржа работает или нет»** и на вопрос
«сейчас идут торги или технический перерыв». Сегодня программа обоих ответов
не имеет: `DOMAIN.md` §3 перечисляет «выходные и нерабочие дни биржи» как один
из случаев, когда робота нет в рынке, но откуда программа узнаёт про выходной —
не сказано нигде.

Что отсюда следует проверить при работе над живым потоком:

⬜ `isWorkDay=false` — робот молчит весь день, и это строка журнала с причиной,
   а не пустой день без объяснения (пункт приёмки: «каждое исключение объяснено
   строкой в журнале»);
⬜ `tradingSessionType = "Технический перерыв QUIK"` — свечи в это время
   не приходят. **Это тот самый случай, когда молчание потока не означает обрыв
   связи.** Расписание отличает одно от другого без догадок;
⬜ `Аукцион открытия` и `Аукцион закрытия` — цены аукциона не то же самое,
   что цены торгового периода; решать по ним нельзя;
⬜ `Вечерняя торговая сессия` — переключатель «выходные сессии» в настройках
   опирается на это же понятие (решение 0007: 106 сделок против 82).

⚠️ Времена в этом ответе — **строки вида `14:30:00` без пояснения о зоне**,
в отличие от `dateTime`-полей, про которые `special_info` прямо говорит «всё UTC».
Проверять живым запросом, а не предполагать: ошибка на три часа сдвинет
торговое окно целиком.

**Что из этого сделано 05.09.2026** (`broker/schedule.py`):

⬜ `isWorkDay`/`isWorkingDay` и типы сессий читаются — на них зоны не нужно;
⬜ времена отрезков отдаются **строками как есть**, арифметики со временем
   суток в слое нет вовсе. Поэтому открытый вопрос №17 (клиринговый перерыв
   на графике) этим методом пока **не закрывается**: поля для ответа есть,
   зона — нет. Установить её может только живой запрос: сравнить `startDate`
   торгового периода с известным расписанием биржи.
