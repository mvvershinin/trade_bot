# 🔒 Ограничения

URL: https://trade-api.bcs.ru/restrictions

Для обеспечения стабильной работы сервисов и равномерного распределения нагрузки
между клиентами, все API-вызовы подчиняются определённым ограничениям по частоте
и объёму запросов. Эти лимиты позволяют предотвратить перегрузку системы, защитить
инфраструктуру от несанкционированного использования и гарантировать предсказуемое
время отклика для всех пользователей.

Ограничения задаются как для HTTP-методов, так и для WebSocket-соединений.
Если клиент превышает лимит запросов, сервер возвращает соответствующий код ошибки
(**429 Too Many Requests**).

## ⚙️ Принцип работы лимитов

- **HTTP** — ограничение по количеству запросов в секунду (RPS) или минуту для каждого счета клиента.
- **WebSocket** — ограничение на частоту подписок, отправку сообщений и общее количество активных соединений.
- **Единая политика** — лимиты могут различаться в зависимости от конкретного сервиса

## 💡 Рекомендации для клиентов

- Реализуйте **обработку кода 429** и повторные попытки с экспоненциальной задержкой.
- Для частых вызовов используйте **кэширование данных** (например, списка инструментов).
- Для потоковых данных предпочитайте **WebSocket**, а не периодические HTTP-запросы.

## Зачем это нам

**Хорошая новость: наши объёмы в лимиты не упираются даже близко.**

Программа торгует **одним** инструментом на пятиминутках. Замер 04.09.2026:
поток даёт ~10 сообщений в минуту на бумагу. Лимит — 10 сообщений в секунду
*от клиента* и 100 инструментов в одном соединении.

Что из этого следует для Э1-5 и дальше:

⬜ **«Для потоковых данных предпочитайте WebSocket, а не периодические HTTP-запросы»** —
   прямое указание документации. Опрос котировок или статуса торгов по HTTP в цикле
   вместо подписки — путь к 429. Наши подозрения про обрыв связи проверяются
   ping/pong (`28-ping-pong.md`), а не опросом;
⬜ **20 одновременных соединений на рыночные данные** — запас огромный, но соединений
   всё равно должно быть одно: переподключение с нарастающей паузой обязано
   **закрывать старое**, иначе после десятка обрывов упрёмся в потолок и получим
   отказ ровно в момент, когда связь только что восстановилась;
⬜ **Заявки: 200 000 в сутки.** Реверсная система на пятиминутках делает
   десятки сделок в день — не проблема. Но это потолок, который стоит помнить
   при скользящем тейке: у него уровень **меняется**, и перестановка на каждой свече
   становится настоящей операцией у брокера (решение 0009). Шаг подтяжки —
   ограничитель нагрузки, и теперь у него есть числовой потолок;
⬜ **`RESOURCE_EXHAUSTED` в поле `type` ответа 429** — машинный признак; в журнал
   он должен попадать человеческим языком, а не кодом (правило слоя `ui/`);
⬜ **экспоненциальная задержка при 429** — то же требование, что уже записано
   в составе Э1-5 для переподключения. Один механизм на оба случая.
