Метод предназначен для получения исторических данных по инструменту.

## Ограничение

Максимальное количество баров в одном запросе — **1440**

Если запрошенный временной интервал с учётом параметра `timeFrame` содержит
**более 1440 свечей**, сервер вернёт ошибку.

### Зачем это ограничение

Ограничение введено для обеспечения стабильной работы сервиса и предсказуемого
времени ответа.

### Как избежать ошибки

- Уменьшите временной интервал (`startDate` / `endDate`)
- Используйте более крупный `timeFrame` (например, `H1` вместо `M5`)
- Разбивайте большой период на несколько последовательных запросов

### Пример

Если вы запрашиваете свечи с таймфреймом `M1`, максимальный допустимый период —
1440 минут. Запрос большего интервала приведёт к ошибке.

## Request — Query Parameters

**classCode** string **required** `non-empty` — Код класса инструмента. **Example:** `TQBR`
**ticker** string **required** `non-empty` — Тикер инструмента. **Example:** `SBER`
**startDate** date-time **required** — Время начала периода. **Example:** `2025-11-14T07:00:00Z`
**endDate** date-time **required** — Время конца периода. **Example:** `2025-11-14T10:00:00Z`
**timeFrame** string **required** — [ `M1` , `M5` , `M15` , `M30` , `H1` , `H4` , `D` , `W` , `MN` ]

`M1` 1 минута · `M5` 5 минут · `M15` 15 минут · `M30` 30 минут · `H1` 1 час ·
`H4` 4 часа · `D` 1 день · `W` 1 неделя · `MN` 1 месяц

## Responses — 200 OK

**ticker** string · **classCode** string · **startDate** date-time · **endDate** date-time ·
**timeFrame** string

**bars** object[]
* **time** date-time **Время открытия свечи**
* **open** number Цена открытия
* **close** number Цена закрытия
* **high** number Максимальная цена
* **low** number Минимальная цена
* **volume** number Объем торгов

```json
{
  "ticker": "SBER",
  "classCode": "TQBR",
  "startDate": "2025-11-14T07:00:00Z",
  "endDate": "2025-11-14T10:00:00Z",
  "timeFrame": "H1",
  "bars": [
    { "time": "2024-07-29T15:51:28.071Z", "open": 0, "close": 0, "high": 0, "low": 0, "volume": 0 }
  ]
}
```

## 400 / 429

Общая форма отказа плюс **свой код: `CANDLE_LIMIT_EXCEEDED`** — превышен предел 1440 баров.

Base URL `https://be.broker.ru/trade-api-market-data-connector`, Bearer JWT.

⚠️ Код `CANDLE_LIMIT_EXCEEDED` в официальном PDF **не назван**: там перечислены
только 401 UNAUTHORIZED, 404 NOT_FOUND («данные не найдены»), 400 BAD_REQUEST,
400 VALIDATION_ERROR и 5xx. Имя кода взято из одностраничной документации сайта
и живьём не проверено.

⚠️ **404 у этого метода двузначен.** По документации это «данные не найдены» —
законный ответ на период без торгов. Но 404 приходит и от шлюза, когда адрес
неверен, и тогда тело — HTML nginx, а не JSON. Различать по телу ответа.

## Зачем это нам

**Это второй источник истории, кроме MOEX ISS.** Сегодня база (76 956 свечей MXU6)
залита из ISS и сверена с эталоном 20 021 из 20 021. Появление второго источника —
не подарок, а риск: у таблицы `minute_candle` есть колонки `source` и `source_rank`
ровно для этого.

⚠️ **Проверить до использования, живым запросом, а не рассуждением:**

⬜ **в чём здесь `volume`** — в контрактах, как у ISS, или в обороте, как в потоке
   WebSocket (замер 04.09.2026: поток даёт цену × количество). Если в обороте,
   то стык ISS ↔ БКС даст тот же разрыв на пять порядков;
⬜ **`time` — «время открытия свечи»**, как и `ts` в нашей базе. Совпадение имён
   ещё не совпадение смысла: у движка окно считается по времени **закрытия**
   (`ARCHITECTURE.md` §2, из-за этого свеча стратегии несёт `closes_at`);
⬜ есть ли расхождение цен с ISS на одних и тех же минутах.

**Практическое ограничение 1440 баров** — это ровно одни сутки минуток. Для догрузки
пропущенного после обрыва связи этого с запасом хватает; для первичной заливки
истории — нет, нужна разбивка по суткам и учёт лимита частоты запросов.
