# Документация БКС Trade API — локальный снимок

**Снято:** 04.09.2026 с сайта `https://trade-api.bcs.ru/` через кнопку
«Копировать для AI → Открыть как Markdown». Тридцать страниц, весь публичный API.

**Зачем копия в git.** Страницы сайта отдаются одностраничным приложением: обычной
загрузкой достаётся только меню, а markdown-выгрузка живёт по `blob:`-адресу
со случайным UUID, который снаружи не открыть. Автоматически выкачать нельзя —
только руками. Поэтому копия лежит в репозитории и переживает чистый клон.

**Главной остаётся живая документация на сайте, а не этот снимок** — правило

Копия нужна для поиска и чтения.

**И сайт, и PDF уже уличены во вранье — проверено живым запросом 04.09.2026:**

| источник | что написано | что на самом деле |
|---|---|---|
| PDF `trade-api-docs.pdf` | поле подписки `subscriberType` | сервер требует `subscribeType` |
| PDF, там же | поле времени `dateTimeUtc`, вложенные контейнеры | приходит `dateTime`, ответ плоский |
| сайт, справочник инструментов | `type` — перечисление латиницей (`FUTURES`) | приходит по-русски («Фьючерсы»); латиницей — `instrumentType` |
| сайт, справочник инструментов | `maturityDate` — `date-time` | приходит строкой `"20260917"` |
| сайт, стакан | `bidVolume` — `number` | в примере строка `"59851"` |
| **сайт и PDF**, справочник инструментов | ответ — объект с контейнером `instruments` | приходит **голый массив** (замер 04.09.2026, разбор чинён 05.09.2026, `B-014`) |
| PDF, справочник | `maturityDate` — `date-time` | приходит `"20260917"` — дата **без пояса**; поле в схеме объявлено с поясом |
| сайт, расписание на день | сервис `trade-api-bff-portfolio` | PDF: `trade-api-information-service`. Живьём **не проверено ни одно**; выбран PDF, разбор — `session.DAILY_SCHEDULE_PATH` |
| сайт, расписание на день | признак рабочего дня `isWorkDay` | PDF: `isWorkingDay`. Живьём не проверено; читаются оба |
| сайт, статус торгов | `nextSessionDate` — `…Z` | пример PDF `2021-01-19T09:41:03` без пояса. Наивный момент отбрасывается |
| **PDF**, портфель | ответ — объект с контейнером `positions` | сайт: **голый массив**. Живьём не проверено ни одно; разбор читает **оба**, третий вид — отказ (05.09.2026) |
| **PDF**, лимиты | контейнеры `moneyLimit`, `futuresLimit` | сайт: `moneyLimits`, `futuresLimits`. Живьём не проверено; читаются оба |
| **PDF**, лимиты | `cbpl.init`, `cbp1Planned`, `cbplusedForOrders`, `accruedInt` | сайт: `cbpLimit`, `cbplPlanned`, `cbplUsedForOrders`, `accruedint`. Таблица PDF набрана с опечатками, читаются все написания |
| **сайт**, дисконты | сервис `trade-api-bff-trade-details` | PDF: `trade-api-bff-marginal-indicators`. Живьём не проверено ни одно; метод в коде не заведён (05.09.2026) |

| **наша выписка**, создание заявки | «Повтор с тем же `clientOrderId` не создаёт вторую заявку» | **в документации этого нет:** названо только назначение поля («для отслеживания и предотвращения дублирующих заявок»), а поведение сервера на повтор — ни кода отказа, ни срока, ни области уникальности. Живьём не проверено. Правка 06.09.2026, `B-002` |

## Что установлено живым подключением 04.09.2026

Токен чтения, MXU6/SPBFUT, M1, 78 сообщений за 9 минут.

⬜ **Брокер шлёт готовые свечи, не тики.** Одна минута приходит 8–14 раз,
   объём нарастающим итогом, `low` монотонно падает, `high` держится. Значит
   `market.storage.put_minutes` (схлопывание последним значением) **верен как есть**.
⬜ **Признака «свеча закрыта» нет.** Закрытие определяется приходом следующей
   минуты либо по часам. Задержка первой свечи новой минуты: **3–17 с, среднее 8,6**.
⬜ **Объём в потоке — оборот в валюте**, в нашей базе (ISS) — контракты.
   30 579 800 ÷ 224 875 = 136,0. Разрыв на пять порядков на стыке.
⬜ **Обмен токена работает:** `expires_in=86400`, `refresh_expires_in≈90 суток`.
⬜ **MXU6 = MIX-9.26**, `classCode` SPBFUT, шаг 25,0, лот 1, экспирация 17.09.2026.
