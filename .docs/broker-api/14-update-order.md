# Изменить заявку

URL: https://trade-api.bcs.ru/http/operations/update-order

```
POST
## https://be.broker.ru/trade-api-bff-operations /api/v1/orders/edit
```

Метод позволяет изменить параметры собственной заявки в допустимом статусе.
**Изменение выполняется через отмену исходной заявки и создание новой заявки
с указанными параметрами.** Заявки со статусом `0` (Новая), `1` (Частично исполнена),
`5` (Заменена) или `10` (Ожидает подтверждения новой заявки) могут быть изменены.

## Request — Body, required

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `orderIdType` | string | нет | `1` — `clientOrderId` исходной заявки (UUID, по умолчанию); `2` — биржевой `orderId`. **Default:** `1` |
| `orderId` | string | да | Идентификатор изменяемой заявки |
| `clientOrderId` | uuid | да | Уникальный идентификатор **новой** заявки — генерируете вы. Для отслеживания и предотвращения дублирующих заявок |
| `orderQuantity` | int64 | да | Количество в заявке (шт.), `>= 1` |
| `orderType` | string | нет | `1` Рыночная · `2` Лимитная · `3` Алгоритмическая GTD · `4` Айсберг · `5` Условная |
| `timeInForce` | string | нет | `1` Day · `2` Fill Or Kill · `3` Good Till Date (только алгоритмические; требует `expiryDate`) |
| `expiryDate` | string | усл. | `YYYYMMDD`, не раньше даты изменения и не позже 30 календарных дней |
| `price` | number | усл. | Цена за штуку, > 0, до 8 знаков |
| `stopPrice` / `takePrice` | number | усл. | Стоп-цена / цена тейк-профита условной заявки |
| `visible` | integer | усл. | Видимое количество айсберга, обязательно при `orderType = "4"` |
| `executionTakeProfitType` / `executionStopLossType` | integer | нет | `1` рыночное, `2` лимитное |
| `spread` / `spreadType` | number / integer | нет | Защитный спред; `0` валюта цены, `1` проценты. **Default:** `0` |
| `offset` / `offsetType` | number / integer | нет | Отступ; `0` валюта цены, `1` проценты. **Default:** `0` |

## Responses

**200 OK** — `clientOrderId` uuid, `status` string (`OK`)
**400 / 401 / 403 / 404 / 422 / 429 / 500** — общая форма отказа плюс `USER_NOT_FOUND`.

Base URL `https://be.broker.ru/trade-api-bff-operations`, Bearer JWT.

## Зачем это нам — прямо про скользящий тейк

⚠️ **«Изменение выполняется через отмену исходной заявки и создание новой»** —
это не деталь реализации, а факт с последствиями в деньгах.

Решение 0009 (скользящий тейк в первом этапе) уже предупреждало: у скользящего тейка
уровень **меняется**, поэтому перестановка на каждой свече становится настоящей
операцией у брокера, а шаг подтяжки превращается из украшения в ограничитель
нагрузки. Теперь известно, во что именно обходится перестановка:

⬜ **между отменой и созданием есть окно, в котором тейка у брокера нет вовсе.**
   Если рынок дошёл до уровня ровно в этот момент — тейк не сработает.
   Это надо назвать в контракте и в журнале, а не обнаружить на счёте;
⬜ каждая перестановка — **две операции** в суточном лимите 200 000, а не одна;
⬜ у новой заявки **новый `clientOrderId`**, значит связь «наш уровень ↔ заявка
   брокера» рвётся на каждой подтяжке и должна переустанавливаться;
⬜ статус `1` (Частично исполнена) тоже изменяем — то есть подтяжка возможна
   поверх частичного исполнения, и что при этом происходит с остатком,
   надо проверить пробой до боевого режима.
