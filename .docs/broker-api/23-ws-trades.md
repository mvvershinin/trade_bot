# Обезличенные сделки (WebSocket)

URL: https://trade-api.bcs.ru/websocket/market-data/trades

WebSocket API предоставляет поток **обезличенных сделок** по инструменту в реальном времени.

## 🔌 WebSocket URL

```text
wss://ws.broker.ru/trade-api-market-data-connector/api/v1/market-data/ws
```

Тот же сокет, что и свечи, — различает `dataType`.

## 📤 Подписка

```json
{
  "subscribeType": 0,
  "dataType": 2,
  "instruments": [ { "ticker": "SBER", "classCode": "TQBR" } ]
}
```

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `subscribeType` | number (enum) | да | `0` — Подписка, `1` — Отписка |
| `dataType` | number (enum) | да | **`2` — Обезличенные сделки** |
| `instruments[].ticker` / `.classCode` | string | да | Инструмент и класс |

## 📥 Ответы

### Подтверждение подписки

```json
{
  "responseType": "LastTradesSuccess",
  "subscribeType": 0,
  "ticker": "SBER",
  "classCode": "TQBR",
  "dateTime": "2024-11-01T10:00:00.000Z"
}
```

### Данные сделки

```json
{
  "responseType": "LastTrades",
  "ticker": "SBER",
  "classCode": "TQBR",
  "side": "BUY",
  "volume": 612,
  "price": 305.89,
  "quantity": 2,
  "dateTime": "2025-11-20T06:29:41.000Z"
}
```

| Поле | Тип | Описание |
|---|---|---|
| `responseType` | string (enum) | `LastTrades` — данные по сделке |
| `ticker` / `classCode` | string | Инструмент и класс |
| `side` | string (enum) | `BUY` — покупка, `SELL` — продажа |
| `volume` | number | **Объём сделки** |
| `price` | number | Цена сделки |
| `quantity` | number | **Количество бумаг в сделке** |
| `dateTime` | string (datetime) | Дата и время обновления данных (UTC) |

Коды ошибок: `NO_DATE`, `NOT_FOUND`, `INCORRECT_JSON`, `BAD_REQUEST`, `UNAUTHORIZED`.

---

## Зачем это нам — точный объём в контрактах

В примере из документации всё сходится: `volume` 612 = `price` 305,89 × `quantity` 2
(с округлением). То есть **`volume` — оборот, `quantity` — штуки**, ровно как
в HTTP-версии (`08-last-trades.md`) и как показал замер потока свечей.

Это даёт **точный** способ получить объём минуты в контрактах: сумма `quantity`
всех сделок минуты — без деления оборота на цену и без накопления погрешности.

⚠️ Но цена такого способа высока, и её надо назвать вслух:

⬜ поток тиков вместо ~10 сообщений в минуту даёт сотни; лимит «10 сообщений
   в секунду **от клиента**» это не нарушает (мы только слушаем), но нагрузка
   на обработчик растёт, а документация требует **не блокировать обработку
   входящих**, иначе рвётся соединение (`28-ping-pong.md`);
⬜ придётся самим собирать минуту из тиков — то есть делать ровно то, от чего
   нас избавляет канал свечей, и заводить второй путь получения одних и тех же
   данных. Два пути разойдутся;
⬜ у истории из ISS всё равно свой объём, и сверять придётся с ней.

**Разумное применение: не как источник, а как эталон для проверки.** Один торговый
день записать обоими каналами и сверить: сумма `quantity` по минуте против
`volume` свечи ÷ цена. Это ответ на вопрос «какая погрешность у пересчёта»,
и он нужен один раз, а не постоянно.
