# Получение дисконтов по инструментам

URL: https://trade-api.bcs.ru/http/get-instruments-discounts

```
GET
## https://be.broker.ru/trade-api-bff-trade-details /api/v1/instruments-discounts
```

## Responses — 200 OK

Массив:

| Поле | Тип | Описание |
|---|---|---|
| `ticker` | string | Тикер инструмента |
| `discountLong` | number | Ставка на лонг |
| `discountShort` | number | Ставка на шорт |

```json
[ { "ticker": "string", "discountLong": 0, "discountShort": 0 } ]
```

## 429 — общая форма отказа, см. `03-limits.md`

Base URL `https://be.broker.ru/trade-api-bff-trade-details`, Bearer JWT. 10 RPS.

⚠️ **Имя сервиса у сайта и PDF разное — найдено 05.09.2026.** Эта выписка снята
с сайта и называет `trade-api-bff-trade-details`; официальный PDF в разделе
«Получение дисконтов» пишет дословно
`GET https://be.broker.ru/trade-api-bff-marginal-indicators/api/v1/instruments-discounts`,
то есть тот же сервис, что у маржинальных показателей. Живьём **не проверено
ни одно**. В коде метод не заведён: адрес в `ALLOWED_READ_PATHS` не вносился,
и вносить его до живой проверки нельзя — цена промаха 404 от шлюза.

---

## Зачем это нам

Дисконт — множитель, по которому считается требуемое обеспечение. **Ставки на лонг
и шорт разные**, и это прямо касается реверсной системы: переворот меняет сторону,
а значит меняет и требуемое ГО — при том же объёме и той же цене.

Следствие, которое надо проверить до боевого режима: расчёт «хватает ли средств
на вход» обязан брать ставку **той стороны, в которую входим**, а не одну общую.
Иначе проверка пройдёт на лонге и не пройдёт на шорте, и робот встанет посреди
торгового дня на перевороте.

⚠️ Кэшировать: документация советует кэшировать справочники (`29-restrictions.md`).
Ставки меняются редко, но меняются.
