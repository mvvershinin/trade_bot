# Получение статуса заявки

URL: https://trade-api.bcs.ru/http/operations/get-order-by-id

```
GET
## https://be.broker.ru/trade-api-bff-operations /api/v1/orders
```

Метод позволяет получить актуальный статус собственной заявки любого поддерживаемого
типа по идентификатору. При отсутствии заявки возвращается ошибка 404 NOT_FOUND.

## Request — Query Parameters

**orderIdType** string [ `1` , `2` ] **Default:** `1`
`1` – Идентификатор заявки, сгенерированный при подаче клиентом, в формате `UUID`
`2` – Идентификатор заявки (например `20260501-TQBR-79628540663`)

**orderId** any **required** — При `orderIdType = "1"` передаётся `clientOrderId` в формате
UUID; при `orderIdType = "2"` — биржевой идентификатор в формате `ГГММДД-КодКласса-НомерЗаявки`.

## Responses — 200 OK

**clientOrderId** uuid **required** Идентификатор запроса
**originalClientOrderId** string Уникальный идентификатор заявки, который вы сгенерировали при её подаче

**data** object[] **required**

* **messageType** string Тип сообщения
* **orderStatus** string Состояние заявки:
  `0` Новая · `1` Частично исполнена · `2` Полностью исполнена · `4` Отменена ·
  `5` Заменена · `6` Отменяется · `8` Отклонена · `9` Заменяется · `10` Ожидает подтверждения новой заявки
* **executionType** string Тип отчета:
  `0` Новая · `1` Частично исполнена · `2` Исполнена · `4` Отменена · `6` Ожидает отмены ·
  `5` Заменена · `8` Отклонена · `9` Приостановлена · `10` Ожидает подтверждения новой ·
  **`11` Сделка** · `12` Статус заявки · `13` Исправлено
* **orderQuantity** number Количество в заявке (шт.)
* **executedQuantity** number Исполненное количество (шт.)
* **lastQuantity** number Количество в текущей сделке (шт.)
* **remainedQuantity** number Оставшееся количество (шт.)
* **ticker** string · **classCode** string
* **side** string `1` Покупка, `2` Продажа
* **orderType** string `1` Рыночная · `2` Лимитная · `3` Алгоритмическая GTD · `4` Айсберг · `5` Условная
* **averagePrice** number Средняя цена исполнения
* **orderId** string Уникальный идентификатор заявки
* **executionId** string **Уникальный идентификатор сделки**
* **price** number Цена заявки
* **currency** string Валюта
* **clientCode** string Код клиента
* **transactionTime** date-time Дата и время транзакции
* **tradeDate** date Дата сделки. Для вечерней сессии FORTS — дата следующей сессии; обычные сделки — дата исполнения
* **orderNumber** string Номер заявки
* **accruedCoupon** number НКД
* **executionValue** number Объем сделки
* **commission** number **Комиссия**
* **securityExchange** string Идентификатор биржи
* **rejectReason** string Причина отклонения заявки
* **timeInForce** integer `1` Day · `2` Fill Or Kill · `3` Good Till Date
* **expiryDate** string `YYYYMMDD`, при `timeInForce = 3`
* **stopPrice** / **takePrice** number Цены условной заявки
* **visible** integer Видимое количество айсберг-заявки
* **spread** number · **spreadType** integer (`0` валюта цены, `1` проценты)
* **offset** number · **offsetType** integer (`0` валюта цены, `1` проценты)

## 400 / 401 / 403 / 404 / 422 / 429 / 500 — общая форма отказа + `USER_NOT_FOUND`

Base URL `https://be.broker.ru/trade-api-bff-operations`, Bearer JWT.

## Зачем это нам — здесь ответ на вторую ловушку Э1-5

**`executionId` — «Уникальный идентификатор сделки», от брокера.**

Долг, заведённый `/risk` 03.09.2026 (`ROADMAP.md`, блок Э1-5), звучал так: сторож
уникальности сделки в журнале работает по ключу
`(session_id, symbol, side, entry_ts, exit_ts)`; на истории он верен, **на живом
потоке разойдётся** — повтор, собранный заново из ответа брокера с его временами
исполнения, отличается на секунды и ляжет второй сделкой. «Прибыль за день»
удвоится, а владелец счёта выбирает объём по числу сделок из этого файла.

Теперь известно, чем лечить: **настоящий идентификатор от брокера отдельной колонкой.**

⚠️ Но `executionId` — это идентификатор **исполнения (fill)**, а не «сделки»
в смысле нашего журнала. Наша сделка — это пара «вход + выход», у неё два разных
исполнения, и при частичном исполнении их может быть больше двух
(`orderStatus = 1` «Частично исполнена», `lastQuantity` — количество в текущей сделке).
Значит правка схемы журнала — не одна колонка, а отдельная таблица исполнений,
из которой собирается сделка. Это работа боевого исполнителя, не Э1-5.

⚠️ Второе: **`commission` приходит от брокера отдельным полем.** Правило 4 проекта
требует комиссию отдельной строкой всегда; здесь есть чем сверить нашу модель
(14 ₽ за контракт на сторону) с фактом.
