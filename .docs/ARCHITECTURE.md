# Архитектура «Терминала»

Слои, зависимости и правила, нарушение которых ломает продукт незаметно.
Основание — [`SPEC.md`](SPEC.md) §5 и §6.

---

## 1. Главное правило, ради которого всё построено

> **Торговый движок не знает, откуда пришла свеча** — от брокера в реальном времени
> или из базы при прогоне на истории.
>
> **Торговый движок не знает, какая стратегия внутри.**
>
> **Стратегия не знает, какой у нас брокер.**

Следствие, которое надо защищать в каждом ревью: расхождение между тестером и боем
**невозможно по построению**. Разойтись могут только цены исполнения — и именно их
показывает наложение прогноза на факт.

Любое изменение, после которого движок начинает различать «живой» и «исторический»
режим, — это архитектурное нарушение, даже если тесты зелёные. Оно возвращает нас
к продукту, где тестер врёт, а доказать это нечем.

## 2. Слои

```
market/       данные: MOEX ISS, сборка таймфрейма, SQLite-хранилище свечей
broker/       БКС: токены, котировки, заявки, портфель, поток реального времени
strategies/   сменные торговые модули; первый — EMA-реверс
engine/       свечи → сигнал → заявка → позиция; окна, паузы, тейк, лимиты, сверка
backtest/     прогон по истории, оптимизатор, метрики, независимый период
ui/           PySide6: график, настройки, журналы
app/          сборка, настройки, запуск, логирование
```

### Зависимости — строго в одну сторону, циклов нет

```
market/         →  (ничего)
broker/         →  (ничего)
strategies/     →  (ничего: типы свечи и сигнала объявлены внутри слоя)
engine/         →  strategies/            через порт «стратегия»
                →  порты «источник свечей» и «исполнитель заявок» — НЕ конкретные модули
backtest/       →  engine/, strategies/, market/
ui/             →  engine/, backtest/, market/   только на чтение и команды
app/            →  все
```

**Где живут типы свечи и сигнала.** `strategies/` не импортирует ни один слой
проекта: общего слоя типов среди семи нет, а `market/`, который свечи производит,
импортировать `strategies/` не может — ему по таблице выше не положено ничего.
Значит типы объявлены внутри `strategies/`.

⚠️ **Соответствие структурным НЕ является, и это решено осознанно 30.08.2026.**
Здесь стояло «`market/` отдаёт объекты нужной формы, ничего не импортируя» — то есть
свеча слоя данных должна была проходить в модуль стратегии утиной типизацией.
От этого отказались при Э1-6, по требованию гейта `/validate`.

Причина в одном поле. У свечи `market/` есть `time` — это **начало** свечи. Движок
считает торговое окно по времени **закрытия** (§6, неравенства строгие). Две величины
различаются на таймфрейм, а имя поля не различается никак — и утиная типизация
пропускает подмену молча. Это уже происходило: формы классов совпали, свеча слоя
данных прошла в окно, и весь график с метками уехал на один бар. Разбор — в докстринге
`ui/models.py`, лечение там же разными именами полей плюс сторожевой тест.

⚠️ **У свечи окна время — открытия, и это не отменяет сказанного** (B-008, 04.09.2026).
Ось графика размечена началами интервалов, потому что так подписывает свечу биржа
и так рисует терминал брокера; поле называется `opens_at`, а не `time`. Имена
по-прежнему разные намеренно: значения совпали, и единственное, что теперь отделяет
свечу слоя данных от свечи окна, — это имя. Перевод соглашения движка (закрытие)
в соглашение оси (открытие) делает `app/convert.py`, одним местом на все ряды графика.

Поэтому свеча `strategies/` несёт **`closes_at`**, а поля `time` у неё нет вовсе;
объект с полем `time` модуль отвергает явной проверкой, а не молча. **Перекладку
свечи из слоя данных в слой стратегии делает `engine/`** — одной явной строкой,
которую видно в ревью. Это стоит одной функции против расхождения сверки, которое
искали бы в стратегии.

Тест направления зависимостей это не затрагивает: он про импорты и остаётся зелёным.

`engine/` объявляет два порта и не знает их реализаций:

| Порт | Боевая реализация | Тестовая реализация |
|---|---|---|
| Источник свечей | поток брокера + догрузка | чтение из SQLite по периоду |
| Исполнитель заявок | заявки в API БКС | модель исполнения с комиссией и проскальзыванием |

Это единственное место, где боевой режим и тестер расходятся. Всё остальное — общий код.

### Запуск из исходников — только `python3 -m app.main`

Слои лежат в корне репозитория, рядом с `app/`. При запуске файлом (`python3 app/main.py`)
Python кладёт в начало пути поиска каталог `app/`, а не корень, и `import market` падает:

```
$ python3 app/main.py
ModuleNotFoundError: No module named 'market'
$ python3 -m app.main
ok
```

Проверено прогоном на этой раскладке 30.08.2026. **Собранный бинарь работает в обоих
случаях** — модули слинкованы внутрь на этапе сборки, — и тесты этого не поймают:
`pythonpath = ["."]` в `pyproject.toml` кладёт корень в путь так же, как `-m`.

Отсюда правило: единственный поддерживаемый способ запуска из исходников — `python3 -m app.main`
из корня репозитория. Оно записано здесь, а не в README, потому что ошибка выглядит как
«слоя `market` не существует» и уводит искать не туда. Лечить её вставкой `sys.path` в
`app/main.py` нельзя: такой костыль со временем начинает тянуть конкретные модули в обход
портов, и это уже нарушение §1.

## 3. Что где живёт

### `strategies/`

Торговый модуль получает закрытые свечи и отдаёт **намерение**: лонг / шорт / ничего.
Он не подаёт заявки, не знает про объём в рублях, комиссию, ГО и торговое окно.

Общие для всех модулей вещи — торговое окно, паузы, тейк, объём, комиссия, лимиты —
живут в `engine/` и **не дублируются в каждом модуле**. Настройки каждого модуля
сохраняются отдельно: переключился туда-обратно — всё на месте.

### `engine/`

Владеет всем, что превращает намерение в позицию:

- торговое окно, дни недели, интервалы паузы, выходные сессии
- режим (реверс / только лонг / только шорт / только закрытие / выключен)
- момент переворота («в одной свече» / «через свечу»)
- тейк-профит и скользящий тейк
- расчёт объёма, потолок объёма, проверка ГО
- дневной лимит убытка
- сверка позиции после обрыва связи
- журнал решений: **каждая строка — событие с причиной**

### `ui/`

**В UI нет торговой логики.** Ни одной. Окно показывает состояние и отправляет команды.
Если для ответа на вопрос «а войдёт ли робот сейчас» нужно посмотреть в `ui/` —
логика утекла и это дефект.

**Где проходит граница — записано после разбора 31.08.2026.** Правило «ни одной»
натыкается на диалог настроек: он сравнивает объём с потолком и пишет предупреждение.
Формально сравнение, по сути — подсказка. Граница такая:

> Окну можно сравнивать значения, которые оно **само же показывает**, и говорить
> об этом словами — пока сравнение не решает, что уйдёт наружу, и не подменяет
> собой отказ движка.

Граница пройдена, как только сравнение начинает **определять** заявку: обрезает
объём, меняет `Settings` перед отправкой, гасит кнопку без права включить её обратно.
Зеркалить жёсткое правило движка окну можно — но источник правды один, условие
совпадает дословно, и ссылка на него стоит рядом (образец: `take_error()` против
`EngineSettings.__post_init__`). Второе правило, изобретённое в окне, — дефект,
даже если оно верное: разойдутся они молча.

### `market/`

Хранилище — **одна встроенная база в одном файле** рядом с программой (SQLite).
Никакого сервера. Резервная копия = копия папки. Перенос = копирование папки.
Реальные котировки от брокера дописываются в ту же базу поверх истории; стыка не видно.

## 4. Стек

| Часть | Чем | Замечания |
|---|---|---|
| Окно | **PySide6 (Qt 6)** | Бесплатна для коммерческого использования |
| График | **TradingView Lightweight Charts**, встроенный в окно | Метки сделок и линии уровней — штатная возможность |
| Хранилище | **SQLite** | Входит в состав Python |
| Связь с брокером | **httpx + websockets** | Асинхронно — график не подвисает |
| Расчёты по свечам | **pandas** | Скользящая средняя, статистика по сделкам |
| Сборка | **Nuitka standalone** | Нативный бинарь: подписи кода нет, а загрузчик PyInstaller попал в списки угроз антивирусов. [Решение 0001](decisions/0001-packaging-nuitka-portable.md) |
| Поставка | **Портатив, установщика нет** | Windows — папка, Linux — один файл AppImage. Не устанавливается ничего; базу создаёт сама программа при первом запуске |

**Запасной вариант по графику.** Если встроенный веб-график не подойдёт (старое окружение
на Linux заказчика) — переход на **pyqtgraph**. Замена затрагивает один блок, а не всю программу.
Из этого следует требование: график изолирован за собственным интерфейсом,
остальная программа не знает, чем он нарисован.

**Про скорость.** Решения принимаются раз в свечу (минуты), а не тысячи раз в секунду.
Запас по скорости многократный. Python здесь не ограничение — и аргумент «перепишем
на компилируемом ради скорости» в этом проекте не принимается без замера.

## 5. Асинхронность

Программа одновременно держит поток котировок, отвечает на действия мышью и рисует график.
Qt и `asyncio` сводятся в один цикл событий:

- **QtAsyncio** (`PySide6.QtAsyncio`) — официальная реализация от Qt, или
- **qasync** — зрелая сторонняя библиотека с `@asyncSlot` и `run_in_executor`

Выбор фиксируется решением в [`decisions/`](decisions/) с обоснованием, а не по вкусу.

**Правила, нарушение которых даёт зависший интерфейс:**

- Сетевые вызовы к брокеру и к ISS — только асинхронно, никогда синхронно в слоте
- Тяжёлые расчёты (перебор параметров в оптимизаторе) — в отдельный поток/процесс
  через executor, а не в цикле событий UI
- Прогресс длинного прогона отдаётся в UI сигналами, а не блокирующим ожиданием

## 6. Что ломает проект незаметно

**Решение внутри свечи.** Алгоритм принимает решения **на закрытии свечи**. Код, который
подглядывает в незакрытую свечу, не падает — он просто даёт результат, недостижимый в бою.
Ловится только чтением и сверкой с прототипом.

**Заглядывание в будущее в тестере.** Использование цены закрытия текущего бара для
решения, принятого на этом же баре, — классический источник прибыльного бэктеста
и убыточной торговли.

**Граница торгового окна.** В прототипе окно считается по времени **закрытия** свечи,
и сравнение строгое: `now > start && now < end`. Свеча, закрывшаяся ровно в 10:05,
в окно **не** попадает. Расхождение здесь даёт разные сделки при одинаковых настройках.

**Тихое различие боевого и тестового пути.** Любое `if режим == тестер` внутри `engine/`
или `strategies/` — нарушение §1.

**Комиссия, посчитанная не там.** Валовая прибыль в этом проекте не результат.
Комиссия учитывается в модели исполнения и показывается отдельной строкой везде.

## 7. Что хранится и где

Всё, что программа создаёт сама, — в **одной папке `userdata/`**
([решение 0003](decisions/0003-runtime-data-location.md); там же сказано, где эта папка
находится при каждом способе запуска — для AppImage это не каталог программы).
Скопировать можно целиком:

| Что | Где | Зачем |
|---|---|---|
| Токен и подключение | отдельный файл настроек с ограниченными правами | доступ к счёту |
| Настройки стратегии и интерфейса | файл настроек | переживает переустановку |
| История и реальные свечи | один файл-база | график и проверка на истории |
| Журналы сделок и решений | тот же файл-база | отчётность |
| Технический лог | текстовые файлы, старые удаляются автоматически | разбор проблем |

**Токен никогда не попадает** в технический лог, в журналы, в экспортируемые отчёты
и в резервные копии, кроме своего файла.
