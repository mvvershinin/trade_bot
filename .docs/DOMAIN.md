# Торговый домен «Терминала»

Термины, правила рынка и цифры, без которых код будет «технически правильным»
и торгово неверным. Источник требований — [`SPEC.md`](SPEC.md) (RFC-001 v1.1 от 28.08.2026).
Открытые вопросы — [`OPEN-QUESTIONS.md`](OPEN-QUESTIONS.md).

---

## 1. Что за продукт

Настольная программа под Windows и Linux. Владелец счёта (не программист) выбирает
инструмент, задаёт настройки полями ввода и нажимает «Старт». Программа сама следит
за рынком, подаёт заявки брокеру БКС и объясняет каждое своё решение.

Один пользователь, один брокерский счёт, **один инструмент за раз**, один активный
торговый модуль. Программа торгует только пока запущена.

## 2. Термины

| Термин | Значение в этом проекте |
|---|---|
| **Свеча** | OHLCV за интервал. Решения принимаются **на закрытии свечи**, никогда внутри неё |
| **Сигнал** | Результат работы торгового модуля на закрытой свече: лонг / шорт / ничего |
| **Позиция** | Открытая сторона рынка: лонг или шорт. Одновременно не более одной |
| **Переворот (реверс)** | Закрытие позиции и открытие противоположной. **Переворот и есть стоп-лосс** |
| **Торговое окно** | Часы внутри дня, когда робот может открывать позиции |
| **Интервал паузы** | Диапазон дат «с — по», когда робот не торгует |
| **ГО** | Гарантийное обеспечение — залог под срочную позицию, биржа меняет его в т.ч. внутри дня |
| **Экспирация** | Дата, после которой срочный контракт перестаёт торговаться |
| **Прогноз** | Где робот **должен был** войти/выйти по расчёту (прогон стратегии по тем же свечам) |
| **Факт** | Где сделка произошла на самом деле (цена и время исполнения у брокера) |
| **Проскальзывание** | Расхождение между прогнозом и фактом по цене |
| **Прототип** | Действующая реализация стратегии, эталон для приёмки модуля №1. Поведение — [`PROTOTYPE.md`](PROTOTYPE.md) |

## 3. Торговый модуль №1 — EMA-реверс

### Главное свойство

Система **реверсная**: робот не «ищет вход и ждёт», а всё время держит сторону рынка.
Отдельного ценового стоп-лосса в основном контуре нет.

- Скользящая средняя строится по ценам **закрытия** свечей. Тип — переключатель
  EMA / SMA, умолчание **EMA** (как у прототипа) — [решение 0004](decisions/0004-four-forks-of-trading-logic.md).
- Закрытие **выше** средней → лонг. **Ниже** → шорт. Неравенства **строгие**.
- Решение — только на закрытии свечи.
- Закрытие **ровно на средней** → настройка с тремя значениями, умолчание «как прототип»:
  ни входа, ни выхода. Это шестое исключение из «всегда в позиции», не описанное в ТЗ —
  см. ниже и [решение 0004](decisions/0004-four-forks-of-trading-logic.md).

### Пять законных исключений из правила «всегда в позиции»

Это не дефекты. Каждое обязано быть объяснено строкой в журнале решений,
иначе приёмка по §9 невозможна.

| Ситуация | Почему позиции нет |
|---|---|
| До открытия и после закрытия торгового окна | Вне окна не входим; на границе выходим в деньги (настройка) |
| Выходные, нерабочие дни биржи, невыбранные дни недели | Торговля выключена целиком |
| Внутри интервала паузы | Отпуск, экспирация, отчётность |
| Сработал тейк и включено «стоп на день после тейка» | До конца дня в рынок не возвращаемся |
| Достигнут дневной лимит убытка | Робот стоит до вмешательства человека |

### Как закрывается позиция — что случится раньше

| Событие | Что происходит |
|---|---|
| Обратный сигнал средней | Закрытие и **сразу** открытие противоположной — это и есть стоп |
| Тейк-профит | Закрытие с прибылью, дальше по настройке «после тейка» |
| Скользящий тейк-профит | Закрытие по уровню, который ехал за ценой |
| Кончилось торговое окно | Принудительное закрытие (если включено) |
| Наступил интервал паузы | Закрытие, новых входов нет |
| Дневной лимит убытка | Закрытие, робот останавливается |

### Момент переворота — развилка, меняющая деньги

| Значение | Поведение |
|---|---|
| **Через свечу** (по умолчанию) | Выход на текущей свече, вход в обратную сторону на следующей — **так делает прототип** |
| **В одной свече** | Выход и вход в обратную сторону подаются подряд, рынок не покидаем |

На пятиминутках это до пяти минут вне рынка на каждом перевороте и другая цена входа.
Пункт приёмки «те же сделки, что у прототипа» проверяется **только** в режиме «через свечу».
В режиме «в одной свече» сделки заведомо другие — и это не дефект.

⚠️ **Умолчание здесь обратно предложению ТЗ §4.4 Б** и выбрано осознанно
([решение 0004](decisions/0004-four-forks-of-trading-logic.md)): все известные замеры —
106 сделок и +9 908 ₽ за 19.06–26.08.2026 — получены в режиме «через свечу». Режим
«в одной свече» не измерен ни разу, и ставить его умолчанием значило бы отправить в бой
настройку, которую никто не мерил. Пересматривается отдельным решением после таблицы Э1-19.

### Режимы

`Выключен` / `лонг и шорт (реверс)` / `только лонг` / `только шорт` / `только закрытие`.
Переключение на ходу, без перезапуска.

⚠️ **Режим «Выключен» не закрывает позицию.** Намеренно: выключение не должно само
по себе приводить к сделке. Но позиция остаётся без присмотра — программа обязана
сказать это прямым текстом крупно в окне.

Все — **отправные точки, а не рекомендации**. И тейк, и границы окна подбирались
на том же отрезке истории, на котором проверялись. Это подгонка, и она проговорена вслух.

| Параметр | По умолчанию | Диапазон | Откуда |
|---|---|---|---|
| Размер свечи | 5 минут | 1/5/15/30 мин, 1ч, 4ч, день | прототип |
| Период средней | 15 | 5–300 | прототип; в программу проверки входят **9, 15, 20** |
| Тип средней | EMA | EMA / SMA | прототип |
| Тейк-профит | 0,5% | 0,1–5% | подбор на июнь–август 2026 |
| После сработавшего тейка | не входить до конца дня | не входить до конца дня / ждать нового сигнала средней / сразу восстановить позицию | прототип, [решение 0004](decisions/0004-four-forks-of-trading-logic.md) |
| Момент переворота | через свечу | через свечу / в одной свече | прототип, [решение 0004](decisions/0004-four-forks-of-trading-logic.md) |
| Цена закрылась ровно на средней | как прототип: ни входа, ни выхода | как прототип / сигнал на лонг / сигнал на шорт | [решение 0004](decisions/0004-four-forks-of-trading-logic.md) |
| Торговое окно | 10:05–11:00 МСК | — | лучшее из четырёх на том же отрезке |
| Закрывать в конце окна | включено | — | прототип |
| Торговля в выходные сессии | выключено | — | ТЗ |
| Дневной лимит убытка | 2,0% от счёта на утро | — | **цифру обязан назвать владелец счёта** |
| Минимальный запас средств | 30% | — | к обсуждению |
| Объём | 1 контракт | — | ТЗ |
| Порог долгого обрыва связи | 30 минут | — | к обсуждению |
| Допустимый уход цены по пропущенному сигналу | 0,3% | — | к обсуждению |

**Дневной лимит убытка считается от размера счёта на начало торгового дня и внутри дня
не пересчитывается** — иначе просадка сама уменьшала бы порог и остановка наступала бы
всё раньше.

## 5. Деньги: комиссия, ГО, объём

### Комиссия

Биржевой сбор из карточки инструмента на сайте МосБиржи **плюс тариф брокера
за контракт**. В замерах использовалось 14 ₽ за контракт на сторону.

⚠️ **Замер 05.09.2026 показал, что оба слагаемых записаны здесь неточно**
([решение 0047](decisions/0047-the-exchange-fee-comes-from-the-exchange.md)).
Биржевой сбор не постоянен: это доля стоимости контракта (0,0066 % у MXU6),
и по карточке он был 14,68 ₽ 04.09.2026 и 14,92 ₽ на следующий день. Брокеру
по тарифу «Трейдер» идёт 1,2 ₽, а не 1 ₽. Рядом биржа объявляет **скальперский**
сбор — ровно половину, для сделки, закрытой внутри той же сессии. Итог за контракт
на сторону выходит 16,12 ₽ по обычному сбору либо 8,66 ₽ по скальперскому,
то есть 14 ₽ занижены на 15 % **или** завышены на 62 %, смотря какой тариф
действует. Какой именно — вопрос №19 в `OPEN-QUESTIONS.md`; до ответа владельца
счёта умолчание 14 ₽ не меняется, и все замеры проекта сделаны при нём.

Комиссия — **всегда отдельная строка** в журнале и в отчёте. Валовая прибыль без
комиссии в этом проекте не является результатом. Реверсная система на пятиминутках
делает много переворотов, и комиссия — первый кандидат съесть весь плюс.
Число переворотов — обязательный показатель отчёта.

### Гарантийное обеспечение

На срочном рынке позиция удерживается под ГО, размер которого биржа пересматривает,
**в том числе внутри дня** при росте волатильности. Если свободных средств перестало
хватать, позицию принудительно закрывает брокер — по своей цене и в свой момент.

Требование: программа видит свободные средства **до** подачи заявки, держит заданный
запас и **не узнаёт о нехватке из отказа брокера**.

### Объём

Единственное поле, где опечатка в один знак меняет последствия в десять раз.
**Жёсткий потолок объёма** задаётся один раз и не превышается ни ручной настройкой,
ни расчётом от процента. Заявка сверх потолка не подаётся, в журнал пишется отказ с причиной.

Изменение объёма действует **со следующей сделки**; уже открытую позицию не трогает —
иначе робот начал бы «доливать» или «отрезать» на ровном месте.

## 6. Брокер БКС: что даёт и чем ограничивает

📖 **Единственный источник правды — официальная документация Trade API БКС:**
`https://trade-api.bcs.ru/http/authorization` (страница авторизации; остальные
разделы — соседние страницы того же сайта). Указание владельца счёта от 30.08.2026:
руководствоваться ею.

⚠️ **Цифры ниже сверены не полностью.** При написании слоя `broker/` выяснилось,
что ограничения «10 запросов в секунду» и «1440 свечей за запрос» в документации
брокера не нашлись — они попали сюда и в приложение А ТЗ из другого источника.
Ограничитель частоты в коде поставлен по осторожному умолчанию, а не по документу.
Перед работой с брокером сверяться с сайтом; расхождение — повод править этот файл,
а не подгонять код.

### Токены

| Факт | Следствие для программы |
|---|---|
| Токен из личного кабинета живёт **90 дней** | Напоминание за 10 дней, крупным текстом |
| Рабочий токен живёт **24 часа** | Программа обновляет сама, пользователь не видит |
| Токен бывает «только чтение» и «торговля + чтение» | Определять тип и **не давать включить боевой режим на токене для чтения** |
| Токен показывается один раз, привязан к одному счёту | Одна кнопка «заменить токен» с инструкцией |

⚠️ Токен = доступ к деньгам. Лежит в отдельном файле рядом с программой (требование
заказчика). Минимальная защита: права только владельцу, исключение из логов,
резервных копий и экспортируемых отчётов.

### Лимиты

- 10 запросов в секунду на большинство сервисов, до 200 000 заявок в сутки.
- Потоки: до 20 соединений на котировки, до 100 инструментов в соединении.
- Исторические свечи: **не более 1440 за один запрос** — длинные периоды качаются частями.
- При превышении брокер отвечает отказом — программа обязана это корректно пережить.

Для нашей задачи (один инструмент, свечи от минуты) все лимиты с большим запасом.

### Глубокая история — не у брокера

Из-за лимита 1440 свечей история за годы берётся из **открытых данных МосБиржи (ISS)** —
бесплатно и без токена. Брокер используется для реального времени и торговли.

**Известная особенность:** пятиминутные свечи ISS не отдаёт вообще. Доступны минутные,
часовые и дневные. Программа берёт минутные и собирает нужный размер сама.
Уже проверено: собранные данные совпали с эталонными построчно.

⚠️ **Часовые и десятиминутные свечи программа не берёт и с ISS — решено 31.08.2026.**
Свеча, собранная **сервером**, не сообщает, сколько минут интервала в ней действительно
было: в ответе этого нет. Объявить её полной — значит получить **разный ряд баров**
для одного и того же отрезка в зависимости от способа загрузки, как только включена
настройка «пропускать неполные свечи». Поэтому с биржи берутся только минутки,
а любой размер свечи собирается из них (`market.aggregate`), где полнота считается
из того, что реально собрано. Ничего при этом не теряется: минутная история глубже
или равна любой другой (замер ниже).

✅ **Замерено 30.08.2026, прежнее утверждение опровергнуто.** Здесь стояло, что ISS
отдаёт внутридневную историю глубиной около двух месяцев. Это неверно: минутные свечи
отдаются с 2012 года (проверено запросами по SBER за 2012, 2015, 2018 годы), а по MXU6
скачано 76 956 минуток за 299 торговых дней — с 06.09.2025 по 29.08.2026.

⚠️ **Ограничение другое, и оно жёстче.** Глубина упирается не в биржу, а в срок жизни
контракта. У фьючерса полная сессия набирается только в те месяцы, когда он ближний:
у MXU6 дней с полной сессией — 78, и 60 из них попали в окно подбора 19.06–26.08.2026.
**Независимого периода на одном контракте практически нет: 18 торговых дней.**

Склейка ближних контрактов (MXZ5 → MXH6 → MXM6 → MXU6) даёт 290 дней полной сессии,
из них 230 вне окна подбора. Но склейка — это открытый вопрос №8 (экспирация),
и в продукте её нет. То есть проверка на независимом периоде упирается не в данные,
а в нерешённый вопрос.

## 7. Обрыв связи — основной сценарий отказа

Заказчик: «обрыв связи — очень важно!!! интернет прерывается часто».
Для реверсной системы это не частный случай: робот, который «всегда в позиции»,
после обрыва не знает, что произошло с рынком и со счётом.

**Пока связи нет — робот не принимает решений вслепую.** Сигналы по устаревшим данным
не подаются.

### При восстановлении — шесть шагов

1. Догрузить пропущенные свечи, достроить среднюю
2. Спросить у брокера **фактическую** позицию: сторона, объём, средняя цена
3. Прогнать алгоритм по догруженным свечам → какая позиция **должна** быть
4. Сравнить факт и расчёт
5. Привести позицию в соответствие или остановиться — по настройке
6. Записать в журнал обе позиции, вывод и действие — человеческим языком

### Таблица расхождений

| Расхождение | Причина | Действие |
|---|---|---|
| Совпало | Ничего не случилось | Работать дальше, «сверка пройдена» |
| Позиции нет, а должна быть | Пропущен вход | Войти по текущей цене / пропустить — по настройке и порогу ухода цены |
| Позиция есть, а не должно | Пропущен выход | Закрыть |
| Сторона противоположна | Пропущен переворот | Перевернуть |
| Объём не совпадает | Частичное исполнение или ручная сделка владельца | Привести объём к расчётному |
| Позиции нет + брокер сообщает о принудительном закрытии | Не хватило ГО | **Остановиться и требовать человека. Автоматически не восстанавливать** |

⚠️ **Чего программа сделать не может.** Пока компьютера нет в сети, робот не торгует.
Никакой настройкой это не лечится. Если обрывы частые и длинные, единственное настоящее
решение — вынести программу на машину с устойчивым каналом.

## 8. Прогноз против факта

Два слоя меток на одном графике, разного цвета и формы, включаются галочками.

| Что видно | Что это значит |
|---|---|
| Метки совпали | Расчёт и исполнение сошлись |
| Факт правее по времени | Заявка ушла с задержкой — смотреть связь и скорость исполнения |
| Факт хуже по цене, всегда в одну сторону | Проскальзывание. Повод для лимитных заявок |
| Прогноз есть, факта нет | Сигнал пропущен. **Обязана быть причина в журнале**: нет связи, не хватило ГО, сработал лимит, отказ брокера |
| Факт есть, прогноза нет | Самое неприятное: сделка, которой алгоритм не предполагал. **Разбирается как дефект** |

Зачем: пока расхождение не видно глазом, спор «стратегия не работает» против
«стратегия работает, а исполнение подводит» неразрешим.

## 9. Чего продукт не делает

- Других брокеров, кроме БКС
- Торговлю вне биржи и иностранные акции
- Веб-версию, мобильное приложение, облачный сервис
- Автономную работу без включённого компьютера
- Управление несколькими счетами из одного окна
- Несколько инструментов одновременно (подтверждено заказчиком: «пока точно один»)
