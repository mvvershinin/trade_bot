# Codex рядом с Claude Code

Адаптация настроек проекта от 06.11.2026 для Codex CLI 0.167.0.
`CLAUDE.md` и `.claude/` не менялись. Код, ветки, база владельца и тесты продукта
при настройке не изменяются. Оба инструмента используют существующую `.docs/`.

## Запуск

```sh
cd /home/mvv/Projects/trade
codex
# либо из другой папки:
codex -C /home/mvv/Projects/trade
# Claude остаётся как раньше:
claude
```

При первом открытии Codex может попросить доверие к проекту и отдельно к хукам.
Проектные настройки действуют только для доверенного проекта; зарегистрированные
хуки проверяются в `/hooks`. В этой настройке нет обхода доверия/песочницы.
Модель выбирается владельцем через `/model`, роли наследуют модель и effort.
Автокомпактация штатная: прежний Claude-хук чтения транскрипта на 300k не переносился.
Ограничение разрастания контекста и краткий HANDOFF сохранены в AGENTS.md.

Начни с задачи или просьбы продолжить по HANDOFF: новая сессия прочитает его начало
и текущий этап. Статус работы не скопирован в настройки, чтобы он не протухал.
Соседние сессии не должны параллельно менять одни и те же файлы. Перед началом
и коммитом проверяется git status; чужие изменения не включаются в коммит автоматически.

## Что перенесено

| Claude | Codex |
|---|---|
| CLAUDE.md | Компактный AGENTS.md с актуальным порядком работы |
| 13 брифов .claude/agents | .codex/agents/*.toml + .codex/roles/*.md |
| Повторяющиеся хвосты брифов | Один .codex/ROLE_RULES.md |
| 14 skills | .agents/skills/*/SKILL.md, вызов `$review`, `$risk` и т. п. |
| live-trading-guard | Копия + Codex JSON-адаптер, проверка перед shell-командой |
| mutation-guard | Копия: staged-проверка перед коммитом и предупреждение при завершении |
| bash-output-guard | Копия: ограничение больших чтений с учётом workdir команды |
| context-budget-guard | Не переносится: он разбирает формат транскриптов Claude |

Старая `.claude/settings.md` противоречит действующему CLAUDE.md: обязательные
агентные ревью после каждой правки не переносились. Корневая сессия — координатор,
один уровень агентов, делегирование только по прямой просьбе владельца.
Исторические брифы сохраняют предметные детали; последние decisions/HANDOFF
выше их примеров, цифр и прежних автоматических цепочек проверок.

Широкие allow/deny Claude не являются permissions Codex и не копировались.
Codex настроен на workspace-write и on-request. Запреты на чтение секретов,
реальные заявки, destructive git и посторонние файлы закреплены в AGENTS.md.
Shell guards — эвристики, не полная изоляция доступа к торговому счёту.

Критик, валидатор и risk в Codex ограничены инструкцией «только проверка»;
у custom subagent нет собственной технической read-only песочницы. Они возвращают
отчёт, файл пишет координатор. Если нужна именно физическая изоляция записи,
используй отдельную корневую сессию `codex -s read-only`.

Субагенты текущей сессии — `/subagents`, общий центр чатов — `/agents`.
