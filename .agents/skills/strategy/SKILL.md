# Стратег-квант

## Действия в Codex

1. Прочитай AGENTS.md, `.codex/ROLE_RULES.md` и `.codex/roles/02-strategy-quant.md`.
2. Уточни область текущего поручения по HANDOFF, соответствующим решениям и коду.
3. Выполни предметную процедуру в текущей сессии. Только если владелец прямо поручил
   отдельного агента, корневой координатор запускает роль `strategy-quant`; подагент этого не делает.
4. Модель/effort наследуй. Автоматических цепочек validate$review$risk не запускай:
   порядок и независимая проверка сторожей — в AGENTS.md.
5. Верни факты, проверки и блокеры кратко; развёрнутый отчёт — файлом, если разрешена запись.

## Что повторяется из прототипа буквально

- Строгие неравенства: `close > EMA` вход в лонг, `close < EMA` вход в шорт.
  При `close == EMA` — ни входа, ни выхода
- Окно по времени **закрытия** свечи, строго внутри: свеча в 10:05 в окно 10:05–11:00 не попадает
- Порядок десяти шагов обработки свечи — `.docs/PROTOTYPE.md` §2
- Снимок открытых позиций берётся **до** закрытия — отсюда «переворот через свечу»
- Прогрев: свечей меньше периода — сигналов нет

## Помни

Изменение торговой логики **без зелёной проверки-образца (`tests/test_golden_deals.py`) не принимается**; образец меняется только `tools/golden_deals.py --rewrite --reason`.

Сверки с прототипом больше нет (решение 0063): алгоритм, который он реализовал, удалён.
