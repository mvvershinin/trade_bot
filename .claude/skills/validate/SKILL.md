# Валидация архитектуры

## Действия

1. Прочитай `.docs/ARCHITECTURE.md`
2. Собери изменение: `git diff` или указанные файлы
3. Запусти Agent: `subagent_type` general-purpose, `model` sonnet,
   правила из `.claude/agents/11-architecture-validator.md`
4. Верни отчёт с вердиктом PASS / FAIL

## Ищи в первую очередь

Любое `if режим == тестер` внутри `engine/` или `strategies/` — нарушение первого уровня.
Оно не падает, тесты остаются зелёными, а продукт возвращается к состоянию
«тестер врёт, доказать нечем».

```
grep -rn: is_backtest, is_live, backtest_mode, if.*тестер, if.*live
          в engine/ и strategies/
```

## Проверка на себе — три вопроса

1. Можно ли заменить весь `ui/` на консольный вывод, не тронув поведение робота?
   Нет → торговая логика в UI
2. Можно ли прогнать `engine/` по свечам из файла, не подключая брокера?
   Нет → движок знает про брокера
3. Можно ли добавить вторую стратегию, не тронув `engine/`?
   Нет → модульность заявлена, но не сделана

## Формат находки

«Нарушен слой» — не находка. «`engine/` импортирует `broker/`, поэтому прогон
на истории потребует подключения к брокеру, и тестер перестанет работать офлайн» — находка.
