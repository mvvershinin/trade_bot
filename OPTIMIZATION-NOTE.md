# Памятка по расходу токенов — прочитать при первом запуске и вынести на обсуждение

Составлено 11.09.2026 по итогам разбора недельного расхода. Автор — Claude из сессии
`life/.mounted`. **Это гипотезы, а не решения.** Обсуди с Мишей до того, как что-то менять.

---

## Факты

За 7 дней (по 11.09.2026) этот проект — **самый дорогой из сорока четырёх**:

```
trade                 230M   30,0% всего расхода   3535 запросов
sibprime-laravel      181M   23,5%                 2934
life/.mounted         122M   15,8%                 1723
остальные 41 проект   235M   30,7%
```

**Разбивка по моделям: 100% Opus 5.** Sonnet, Haiku и Fable за неделю не вызывались ни разу.

**Где именно уходит:** выход 4,2M токенов даёт около 21M веса. Остальные ~209M — это вход
и кэш, то есть **перечитывание контекста**. Примерно 55 тысяч токенов контекста на запрос
в среднем. Жрёт не генерация кода, а то, что при каждом «поправь вот тут» заново
протаскивается вся накопленная сессия.

Метод подсчёта воспроизводим: транскрипты лежат в `~/.claude/projects/<slug>/*.jsonl`,
в каждой строке assistant-сообщения есть `message.usage` и `message.model`.

---

## Что предлагается обсудить

### 1. CLAUDE.md — 503 строки

Это примерно 6–8 тысяч токенов, которые входят в **каждый** запрос. При 3535 запросах
за неделю — двадцать с лишним миллионов только на него. Почти десятая часть расхода проекта.

**Предложение:** оставить в CLAUDE.md карту и железные правила, детали вынести в файлы,
которые читаются по теме. Ориентир — 150 строк вместо 500.

Образец такого устройства — `~/life/.mounted/CLAUDE.md`: там таблица «когда что читать»
и правила, а содержание в отдельных файлах.

**Почему первым:** одна правка, нулевой риск, эффект виден сразу.

### 2. Модели у агентов — 11 из 14 на Opus

Сейчас:

```
opus     00-coordinator, 01-trading-business-expert, 02-strategy-quant,
         03-backtest-methodologist, 04-broker-expert, 05-data-expert,
         06-desktop-ui-expert, 08-risk-security-officer, 09-parity-auditor,
         11-architecture-validator, 12-code-critic, 13-test-expert
sonnet   07-packaging-expert, 10-product-owner
```

**Гипотеза деления** — Opus там, где решение неочевидно и ошибка дорогая; Sonnet там,
где есть спецификация и её надо применить:

| Оставить Opus | Кандидаты на Sonnet |
|---|---|
| `00-coordinator` | `05-data-expert` |
| `12-code-critic` | `13-test-expert` |
| `11-architecture-validator` | `06-desktop-ui-expert` |
| `02-strategy-quant` | `04-broker-expert` |
| `08-risk-security-officer` | `03-backtest-methodologist` |
| | `01-trading-business-expert` |
| | `09-parity-auditor` |

**Важная оговорка:** деление сделано по названиям файлов и строке `model:`. Содержимое
промптов не читалось. Правь по факту — ты знаешь, что внутри.

### 3. Размер промптов агентов

```
00-coordinator              401 строка
04-broker-expert            369
02-strategy-quant           356
03-backtest-methodologist   330
06-desktop-ui-expert        316
11-architecture-validator   297
...
```

Каждый запуск агента тащит весь его промпт. Если координатор дёргает трёх подряд — это
полторы тысячи строк инструкций поверх самой задачи.

**Предложение:** пройтись и посмотреть, сколько там реально работающего, а сколько написано
«на всякий случай». Правило простое: если строка ни разу не повлияла на поведение — она
платная и бесполезная.

### 4. Дробление сессий

Не про конфигурацию, а про режим работы. Трёхчасовая отладка в одной сессии — к концу
каждый вопрос стоит как десять в начале, потому что контекст перечитывается целиком.

**Приём:** закончил кусок → записал в файл, что сделано и где остановился → `/clear` →
новая сессия читает файл и продолжает. Состояние живёт в файле, а не в контексте.

---

## Что НЕ делать без Миши

- Не менять модели у агентов молча — он может знать, почему конкретный стоит на Opus
- Не резать CLAUDE.md по своему усмотрению — там могут быть правила, купленные болью
- Не трогать промпты агентов без согласования

**Порядок:** прочитать → вынести на обсуждение → дождаться решения → менять.
