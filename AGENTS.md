# «Терминал» — инструкции для Codex

Настольная программа автоматической торговли через БКС: Python 3.12, PySide6,
SQLite, Windows/Linux. Пользователь — владелец счёта, не программист.
Исходные `CLAUDE.md` и `.claude/` принадлежат Claude Code: при настройке Codex их не менять.

## Начало работы и приоритет источников

1. Проверь `git status --short`: дерево общее с другими сессиями. Чужие изменения не откатывать.
2. Прочитай начало `.docs/HANDOFF.md` (последняя запись), затем нужный этап `.docs/ROADMAP.md`.
3. Для содержательной работы — `.docs/ARCHITECTURE.md`, затем документы только по задаче:

| Тема | Источник |
|---|---|
| Торговля, комиссия, ГО | `.docs/DOMAIN.md` |
| Порядок обработки свечи | `.docs/PROTOTYPE.md` §2 |
| Принятые решения | `.docs/decisions/` — найти относящиеся к задаче |
| Проверки, пороги, команды | `.docs/TESTING.md` |
| Открытый вопрос заказчику | `.docs/OPEN-QUESTIONS.md`, список наверху |
| Честность замеров | `.docs/QUALITY.md`, `.docs/quality/FINDINGS.md` |
| Требования | `.docs/SPEC.md` — локально, вне git |
| Баги и долги | `.docs/BACKLOG.md` — искать по теме, не загружать целиком |

Последнее датированное решение владельца выше старых брифов и чеклистов. Статус берётся
из текущего HANDOFF/ROADMAP и кода, не из чисел в историческом CLAUDE.md.
Не возвращать отменённые предохранители/поведение по старому брифу. Конфликт — назвать
оба источника, не объявлять устаревшее требование блокером без проверки решения.
Документация брокера на официальном сайте выше локального снимка: поля, ошибки,
лимиты, сроки токенов проверять там; доступ к счёту для этого не нужен.

## Работа и агенты

- Описание требований — обсуждение/документ; код — после явного поручения.
- Работай по текущему этапу. Случайную находку запиши строкой в BACKLOG и продолжай задачу.
- Одна правка в одном файле не требует миниплана. Новая фича/рефакторинг/крупная задача:
  миниплан в `.docs/plans/`, ссылка в ROADMAP; сначала покажи план владельцу.
- Корневая сессия выполняет роль координатора. Подагенты — только по прямой просьбе владельца.
  Один уровень: владелец → корневой координатор → исполнитель → отчёт координатору.
  Подагент не запускает других агентов и не поручает работу соседям.
- Не запускай ревью/валидацию после каждой правки автоматически. Запрос владельца
  `$review` — один проход; находки не превращать в бесконечную очередь ревью.
- Исключение проекта: изменённое поведение теста-сторожа независимо проверяет `test-expert`
  мутацией именно этого поведения. Поручение идёт через корневого координатора.
  Мутации — только в отдельной копии/дереве, никогда в общем рабочем каталоге.
- Модель/effort наследуются от сессии. Самовольно усиливать модель/effort нельзя.
  Соответствия Opus→модель Codex нет; старые имена моделей не являются настройкой Codex.
- Skills — `.agents/skills/`, роли — `.codex/agents/`, подробные брифы — `.codex/roles/`.
  `$orchestrate` — план; `$domain`, `$strategy`, `$backtest`, `$broker`, `$data`, `$ui`,
  `$package`, `$risk`, `$roadmap`, `$validate`, `$review`, `$test`, `$go-live` — по запросу.
  Название навыка само по себе не разрешает дополнительных агентов или цикл гейтов.
- Критик, валидатор, risk — только проверка. У Codex их запрет записи в брифе
  поведенческий, не отдельная техническая песочница. Для физической изоляции запускай
  отдельную сессию `codex -s read-only`, не выдавай декларацию роли за контроль доступа.

## Правила продукта

- Движок не знает источник свечи и режим live/backtest, стратегия не знает брокера.
  Направления импортов и порты — ARCHITECTURE; торговой логики в UI нет.
- Окно — по времени закрытия свечи, строгие неравенства. Порядок десяти шагов
  PROTOTYPE §2 сохраняется; снимок позиций — до закрытия.
- Комиссия отдельно; результат подбора и независимого периода рядом. Временные
  параметры не выдавать за подтверждённые замеры.
- Любая изменяемая торговая цифра — настройка в окне: значение, подпись, валидация,
  журнал решений, снимок прогона. Фиксированные внешние регламентные числа — исключение.
- Имена переменных, классов, ключей, файлов, каталогов — латиница; русский — в тексте
  для человека. Переименовывать разбором, не слепым sed. Паттерн до третьей ветки;
  паттерн ради паттерна запрещён.
- Токен не попадает в лог, исключения, отчёты, экспорт или фикстуры, ни частично,
  ни целиком. В разработке — симуляция, без боевого токена и реальных заявок.
  Включение боя и первая настоящая заявка — действие владельца после `$go-live`.
- Отказ обязан дойти до человека. Молчание — дефект; мутация отказа не заменяет мутацию молчания.
- Проверка сборки: пустая папка → запуск → кнопка → результат на пути пользователя.
  Консольный тест и offscreen-снимок это не заменяют. Исходники: `.venv/bin/python -m app.main`.
- Тест изолирован: своё состояние, подставной внешний вход, поведение своего предмета.
  Не трогать настоящую `userdata/` в проверках; актуальные ограничения — TESTING/HANDOFF.

## Проверки

После изменения кода: `.venv/bin/ruff check .`, `.venv/bin/mypy`,
`.venv/bin/pytest -n auto -q -m "not slow"`. Сравни с текущими порогами TESTING,
известный долг не лечить попутно. Для настройки инструкций/хуков достаточно их
синтаксических проверок и изолированных сценариев; продуктовый pytest без причины не нужен.
Перед коммитом — полный pytest без фильтра; торговая логика — обязательно
`tests/test_golden_deals.py`. CI без локальных эталонных данных образец не подтверждает.
Образец меняется только `tools/golden_deals.py --rewrite --reason` и по задаче.
Заявки/объём/ГО/токен — `$risk`; боевой режим — `$go-live`, с учётом последних решений.

## Контекст, документы и отчёт

- Ищи `rg` в конкретных каталогах; не обходи `reference/` рекурсивно. Нужный архивный
  файл — по прямому пути из `reference/README.md`; секреты и `.env` не читать без просьбы.
- Большие файлы — поиск/диапазон. Выдача команд с ограничителем, `max_output_tokens`
  по ожидаемому объёму. Не загружать все роли/документы на старте.
- Контекст не растить до 300k: используй штатную компактацию Codex; перед ней и при передаче
  обнови HANDOFF кратко: сделано, открыто, следующий шаг, проверки. Компрессия не заменяет HANDOFF.
- Баг/долг → BACKLOG; вопрос заказчику → OPEN-QUESTIONS и список наверху;
  решение → decisions; замер → quality; новый показываемый этап → ROADMAP по решению владельца.
- Развёрнутый отчёт — файл `.docs/coordination/`, `.docs/reviews/` или `.docs/risk/` по теме;
  в ответ — факты, блокеры, вердикт, путь. Read-only проверяющий возвращает компактный
  отчёт координатору, файл пишет координатор. Не дублируй большие отчёты в диалог.
- Не проверил — так и напиши. Без «готово/отлично работает», без приукрашивания,
  без упоминаний AI в продуктовом коде и коммитах. Не угадывать исправление после ошибки.

## Git и совместная работа

Не добавляй `reference/`, `.docs/SPEC.md`, `userdata/` и секреты, даже через `git add -f`.
`tools/spread_drift.py` и `tests/test_spread_drift.py` оставлены вне git по решению владельца.
Перед коммитом/публикацией проверь только относящиеся к задаче файлы и staged diff;
`git add -A` не является разрешением включить чужие незакоммиченные изменения.
Не делай коммит/push без поручения. Разрушительные операции (удаление проекта/.git,
force push, reset --hard, удаление репозитория) — только с явного согласия владельца.
Свои фоновые процессы снимай по своему PID; не используй общий `pkill`.
