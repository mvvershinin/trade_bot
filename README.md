# «Терминал»

Настольная программа для автоматической торговли фьючерсами на Московской бирже
через торговое API брокера БКС. Одна программа под Windows и Linux, портативная
поставка без установщика.

> ⚠️ **Состояние: боевого запуска не было ни разу.** Программа собирается, работает
> на чистой машине, качает историю, считает прогоны и показывает решения робота
> на живом потоке — но **заявки брокеру не подаются ни из одной ветки кода**.
> Что готово, а что нет, перечислено в [`.docs/ROADMAP.md`](.docs/ROADMAP.md)
> и [`.docs/BACKLOG.md`](.docs/BACKLOG.md) — включая то, что не работает.

---

## Зачем и для кого

Владелец счёта торгует по механической стратегии, которую до этого исполнял
руками и в чужой платформе. Задача — своя программа, которая:

* **делает то же самое сама**, и это можно проверить сделка в сделку;
* **запускается двойным щелчком** на машине без Python, без консоли и без установки;
* **говорит по-русски и человеческим языком** — пользователь не программист;
* **не может потерять деньги молча** — любой отказ доезжает до человека словами.

Последний пункт — не пожелание, а причина половины кода. Программа, которая знает
ответ и не сказала его, в этом проекте считается сломанной.

## Сборка и запуск

Всё в одном месте — [**`BUILD.md`**](BUILD.md), три раздела по трём читателям:

* **запуск из исходников** — `uv`, ключи командной строки, команды проверок;
* **сборка портативной поставки** — Nuitka, отдельно Windows и Linux, что проверять
  перед сдачей;
* **запуск готовой программы** — раскладка папки, куда класть токен, чего ждать
  от антивируса.

Там же: почему готовые сборки не кладутся в репозиторий и где им место.

Установка окружения и обновление зависимостей — [`INSTALL.md`](INSTALL.md).

## Как устроено

Семь слоёв, зависимости строго в одну сторону, циклов нет.

```
                    ┌──────────────────────────────────────────┐
                    │                  app/                    │
                    │   запуск, настройки, журналы, сборка      │
                    └───────┬───────────────┬──────────────┬───┘
                            │               │              │
              ┌─────────────▼──┐   ┌────────▼───────┐  ┌───▼──────┐
              │      ui/       │   │   backtest/    │  │ broker/  │
              │  PySide6:      │   │ прогон по      │  │ БКС: то- │
              │  график,       │   │ истории,       │  │ кен, ко- │
              │  журналы,      │   │ перебор,       │  │ тировки, │
              │  настройки     │   │ метрики        │  │ поток,   │
              └───────┬────────┘   └───────┬────────┘  │ заявки   │
                      │                    │           └──────────┘
                      └────────┬───────────┘
                               │
                    ┌──────────▼───────────┐
                    │       engine/        │
                    │  свеча → сигнал →    │
                    │  заявка → позиция    │
                    │  окно, тейк, лимиты  │
                    └──────────┬───────────┘
                               │  порт «стратегия»
                    ┌──────────▼───────────┐        ┌──────────────┐
                    │     strategies/      │        │   market/    │
                    │  сменные модули,     │        │ MOEX ISS,    │
                    │  первый — EMA-реверс │        │ сборка тайм- │
                    └──────────────────────┘        │ фрейма,      │
                                                    │ SQLite       │
                                                    └──────────────┘
```

### Главное правило: движок не знает, откуда пришла свеча

`engine/` получает свечи через **порт**, а не из конкретного модуля. Кто за портом —
файл с историей, живой поток брокера или подставной ряд из теста — движку неизвестно
и не должно быть известно.

Любое `if режим == тестер` внутри `engine/` или `strategies/` — архитектурное
нарушение. Оно ничего не ломает сразу, тесты остаются зелёными, а продукт
возвращается к состоянию «тестер врёт, доказать нечем».

Отсюда же следует, что **один и тот же движок** обслуживает прогон по истории
и наблюдение за живым рынком, и это проверяется тестом: живой ход и прогон
по истории на одном ряде дают равный результат поле в поле.

---

## Чем это проверяется

Проверка здесь — не побочная работа, а половина проекта, потому что ошибка стоит
денег на счёте.

| Что | Как |
|---|---|
| **Совпадение с действующей реализацией** | Сверка сделка в сделку на одних данных: **127 из 127** |
| **Тесты** | 3599 проверок, полный прогон 31 с, быстрый 16 с |
| **Сторож обязан падать** | Каждая проверка ломается мутацией продуктового кода — тест, который не падает на поломке, считается отсутствующим |
| **Тест изолирован** | Каждый тест обязан давать один результат в одиночку и в компании: прогон всех 3413 тестов по одному вскрыл 18 таких, где это было не так |
| **Молчание — дефект** | Отдельный класс мутаций: сломать так, чтобы отказ **перестал доезжать** до человека. Проверка «команда отвергнута» зеленеет и при молчаливом провале |
| **Прогон безэкранный** | `DISPLAY` убирается из окружения: машина разработчика ведёт себя как сборочный контейнер без монитора |
| **Секреты** | Токен не попадает в лог, журнал, отчёт, экспорт, текст исключения и трассировку. Проверяется мутацией **утечки**, а не отказа |

Линтер и типы **не зелёные** — 575 замечаний `ruff` и 190 `mypy` на момент публикации.
Это разобранный остаток с известными причинами, а не мусор: ни одно нарушение
не подавлено, и числа сравниваются от прогона к прогону.

## Стратегия, коротко

Реверсная система на пятиминутках: цена пересекает скользящую среднюю — вход,
обратное пересечение — переворот позиции. Стопа нет, стопом служит переворот.

| Параметр | Умолчание |
|---|---|
| Средняя | EMA, период 15 |
| Размер свечи | 5 минут |
| Тейк-профит | 0,5 % |
| Торговое окно | 10:05–11:00 МСК |
| Комиссия | 14 ₽ за контракт на сторону |

⚠️ **Эти числа получены перебором на том же отрезке истории, на котором
проверялись.** Первый же прогон на годе данных показал, что на независимом периоде
они убыточны. Поэтому любая таблица результатов в проекте показывает независимый
период **рядом** с подбором, и вторую колонку нельзя скрыть.

⚠️ **Комиссия — всегда отдельная строка.** Валовая прибыль без комиссии здесь
не результат: реверсная система делает десятки переворотов, и комиссия съедает
больше половины валовой.

## Чего здесь нет

Честнее сказать прямо, чем дать обнаружить:

* **боевой торговли** — заявки не подаются, `OrderExecutor` не написан;
* **проверки на живом рынке** — сверка графиков с терминалом брокера не проведена;
* **зелёного линтера** — см. выше, 575 и 190;
* **CI** — сборка и прогон запускаются руками;
* **полного тестового окружения в свежем клоне** — архив с эталоном прототипа
  и полное ТЗ намеренно оставлены за пределами репозитория, поэтому часть
  сверочных тестов там пропустится с явным сообщением, а не тихо.

## Лицензия

Учебный и портфельный проект. Торговля фьючерсами связана с риском полной потери
средств; числа в этом репозитории получены на истории и ничего не обещают.
